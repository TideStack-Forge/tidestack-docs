# 布局组件

布局组件负责平台顶栏、侧栏、导航和品牌展示。开发者可以让 AI 根据设计与宿主契约实现布局，再通过平台应用配置关联组件。

## 准备布局任务

提供需要替换的区域、设计稿、现有布局工程、SDK 版本与菜单样例。说明响应式行为、当前用户展示、主题和应用切换要求，并列出空菜单与权限变化时的表现。

布局消费宿主已有的状态和导航能力：

| 宿主能力 | 布局用途 |
| --- | --- |
| 菜单数据 | 侧栏、导航树和快捷入口 |
| 用户信息 | 头像、当前身份和个人菜单 |
| 主题信息 | 品牌色、深浅模式与框架样式 |
| 路由跳转 | 导航点击后切换宿主页面 |
| 面包屑与应用信息 | 当前路径、标题和应用上下文 |

实际注入方式和类型见 [SDK 初始化方法](../../../../api/frontend/sdk/initialization-methods/)。让 AI 根据目标版本实现，保留宿主的菜单权限过滤与导航链路。

## 实现与配置

1. 在现有工程中实现需要替换的区域，不注入自己的页面路由。
2. 按 [应用改造](../application-transformation) 接入生命周期、容器和资源路径。
3. 构建 ZIP，在 [微前端包管理](../index.md#configuration) 中选择类型 **微前端组件**。
4. 在“应用配置”中关联自定义顶栏或侧边栏入口。
5. 若顶栏和侧栏同时定制，统一维护样式、状态和交互契约。

业务表单、列表和状态流转继续放在 [页面实现](../micro-app/)中。布局接入宿主上下文，不额外维护一套业务状态或用户权限。

## 验证布局

- 不同角色看到的菜单与宿主授权一致，直接接口调用仍由后端控制。
- 当前页面、面包屑和选中菜单一致，应用切换后上下文更新。
- 不同宽度、主题与用户状态下布局可操作。
- 卸载与重新挂载后监听得到清理，导航与用户信息继续正确更新。

AI 排查时使用实际菜单、路由与交互结果定位，跨应用分发见 [平台组件库](../../../../fusion-development/workbench-widgets-and-component-libraries)。
