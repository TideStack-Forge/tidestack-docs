# 审批流

审批流用于需要人工决策、待办流转和过程留痕的业务，例如请假、采购、合同、付款和变更申请。

## 何时使用

| 需求 | 使用能力 |
| --- | --- |
| 多人按顺序、条件或会签规则处理 | 审批流 |
| 系统自动校验、计算、写数据或调用接口 | [逻辑流](../../tutorial/logicflow/) |
| 向申请人或审批人发送结果、待办提醒 | [消息通知](../notification/) |

同一业务可以组合三种能力：审批流负责人机流转，逻辑流负责自动处理，通知负责触达。

## 开始前准备

| 准备项 | 要求 | 配置入口 |
| --- | --- | --- |
| 参与人 | 发起人、审批人、管理员均能映射到明确的用户、员工、部门或岗位 | [组织架构管理](../organization/)、[用户角色权限](../rbac/) |
| 业务数据 | 明确申请表单、业务主键、状态字段和审批中可编辑字段 | [业务模型](../../tutorial/business-model/) |
| 权限 | 明确谁能发起、审批、管理流程和查看统计 | [用户角色权限](../rbac/) |
| 通知 | 明确待办、通过、驳回分别通知谁以及使用哪个渠道 | [消息通知模板与渠道配置](../../tutorial/notification/) |

## 交付顺序

```text
定义流程 -> 部署上线 -> 发起流程 -> 处理与统计
```

1. 在 [审批流管理](./approval-management/) 创建流程，配置节点、连线、候选人和分支条件。
2. 保存并部署流程。部署成功后，目标用户应能在发起入口找到该流程。
3. 使用 [发起审批](./approval-start/) 提交一条测试申请，记录流程实例和业务单据。
4. 使用审批人账号进入 [审批中心](./approval-center/) 处理待办，验证通过、驳回和退回路径。
5. 在 [审批流统计](./approval-statistics/) 查询实例状态、当前节点和处理记录。

验收时至少确认：发起人能提交；审批人能收到并处理待办；业务状态随流程结果更新；处理记录可追溯；通知按配置触达。

## 四个管理入口

| 入口 | 使用者 | 用途 |
| --- | --- | --- |
| [审批流管理](./approval-management/) | 流程设计人员、管理员 | 创建、部署、下线和维护流程定义 |
| [发起审批](./approval-start/) | 业务申请人 | 选择流程并提交申请 |
| [审批中心](./approval-center/) | 审批人 | 查看和处理待办 |
| [审批流统计](./approval-statistics/) | 管理员、支持人员 | 查询实例、处理记录和异常状态 |

## 常见问题

- 找不到审批人：检查员工与用户关联、部门/岗位归属以及节点候选人规则。
- 发起人看不到流程：检查流程是否已部署，以及发起权限是否包含当前用户或角色。
- 审批完成后业务数据未更新：检查流程结果与业务状态的映射，以及审批后逻辑流是否执行成功。
- 用户未收到待办通知：先确认待办已经生成，再检查通知模板、接收人地址和渠道配置。

完整交付关系见 [流程、规则与自动化](../../../low-code/workflow-rules-and-automation) 和 [审批流模型](../../../concepts/approval-workflow-model/)。
