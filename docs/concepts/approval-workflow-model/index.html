审批流模型

审批流模型描述人员参与的长流程，包括申请、候选人、审批节点、分支、驳回、转办和结束状态。它强调跨请求、跨时间的业务状态，不是即时机器处理流程。

作用​

  • 把请假、报销、采购、合同等申请审批过程结构化。
  • 统一流程定义、候选人解析、任务操作、通知和审计关联。
  • 通过版本化定义和引擎适配支持保存、刷新、部署、发起和运行。
  • 将业务数据、页面表单和审批状态连接起来。

核心属性​

属性作用说明
formatVersion定义格式版本区分历史流程定义和当前图结构格式。
name / title / description流程身份与说明供应用、设计器和运行时识别。
version流程版本关联部署、更新和历史实例。
enabled是否启用控制流程是否允许新实例发起。
form业务表单描述申请和审批页面使用的数据载体。
notification通知配置描述待办、结果或异常通知的触发和模板关联。
nodes节点集合包含开始、审批、条件、服务和结束等节点。
edges连线集合描述节点之间的流转和条件。
editorLayout设计器布局保存节点位置等编辑态信息。

与其他模型的关系​

  • 业务模型 提供被审批的业务对象和状态字段。
  • UI Schema 或标准页面提供发起、处理和查看表单。
  • 组织模型 提供公司、部门、岗位和人员上下文。
  • 权限模型 决定谁能发起、处理和查看流程。
  • 逻辑流模型 处理审批前后的自动动作，通知资源负责消息投递。

审批流与逻辑流​

审批流是“人参与、跨时段、有待办状态”的流程；逻辑流是“机器执行、通常一次调用内完成”的流程。审批流可以调用逻辑流完成校验、写入、通知或外部集成，但不应把逻辑流当作审批状态机。

生命周期​

开发平台保存定义后，应用提交并加载元数据；运行时刷新形成流程模型；显式部署后才交给工作流引擎；部署成功后才能发起新实例。保存、刷新和部署不是同一个动作。

使用入口与契约​

  • 操作入口：审批流专题 · 审批流菜单
  • Schema：approval-workflow.schema.json，完整索引见 JSON Schema 参考。
