# 组织模型

组织模型描述公司、部门、岗位、员工和任职关系，为权限、审批、数据范围和业务上下文提供组织事实来源。它不等同于登录认证，也不直接替代 RBAC。

## 作用

- 表达组织树、人员归属、岗位和任职关系。
- 为 [权限模型](../authority-model/) 提供主体、角色和数据范围判断所需的组织上下文。
- 为 [审批流模型](../approval-workflow-model/) 提供候选人、岗位和组织关系。
- 为业务模型的组织字段和页面选择器提供统一来源。

## 核心属性

| 属性 | 作用 | 说明 |
| --- | --- | --- |
| 组织节点标识 | 标识公司、部门等节点 | 用于表达树形层级和归属关系。 |
| 节点类型 | 区分公司、部门等组织对象 | 决定可用属性和下级关系。 |
| `key` / `name` | 岗位标识与名称 | 岗位定义的稳定编码和显示名称。 |
| `level` | 岗位层级 | 支持岗位分级和组织规则判断。 |
| 员工与用户关联 | 连接人员与登录主体 | 组织人员是组织事实，用户认证由安全体系负责。 |
| 任职关系 | 表达人员在组织中的任职 | 支持一人多岗或跨组织任职等关系。 |

## 与其他模型的关系

- [权限模型](../authority-model/) 使用组织、岗位和人员确定授权主体与数据范围。
- [审批流模型](../approval-workflow-model/) 使用组织关系解析审批候选人。
- [业务模型](../business-model/) 可以把组织节点、员工或岗位作为字段引用。
- [菜单模型](../menu-model/) 和 UI 模型只负责入口，不能代替组织权限判断。

## 设计边界

组织模型提供“谁属于哪里、担任什么岗位”的事实；认证系统回答“谁登录了”，权限模型回答“登录后能做什么”。三者必须保持分工。

## 使用入口与契约

- 操作入口：[组织架构](../../guide/module/organization/) · [内置岗位管理](../../low-code/development-platform-menus/builtin-position)
- Schema：岗位资源使用 `position.schema.json`；公司、部门、员工和任职关系以组织模块 API 与运行时模型为准，完整索引见 [JSON Schema 参考](../../reference/jsonschema/)。
