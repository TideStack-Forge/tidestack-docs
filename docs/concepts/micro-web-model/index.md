# 微前端模型

微前端模型登记独立前端资源，让统一前端基座能够发现和加载它们。定义包含资源名称、类型、入口和静态资源路径，也可以关联随应用交付的资源包。页面入口仍由 UI 模型定义，业务访问仍通过后端接口完成。

## 页面、视图与服务三种资源

| 类型 | 用途 | 接入时关注 |
| --- | --- | --- |
| `app` | 独立页面应用，默认类型 | 页面入口、挂载与卸载、路由和认证衔接。 |
| `parcels` | 可嵌入其他页面的视图 | 宿主如何加载、传入参数以及释放视图。 |
| `library` | 可被其他前端消费的服务或库 | 导出能力、加载顺序和依赖约定。 |

类型声明选择资源用途，实际资源仍需实现前端基座要求的接入协议。把普通静态页面填成 `app`，不会自动获得微前端生命周期；`parcels` 和 `library` 也不需要为每个资源强行创建独立菜单。

## 名称、入口和资源路径

`name` 是应用内引用微前端的稳定名称，`entry` 是加载入口，`publicPath` 是静态资源的发布基路径。三者不能互相替代。

下面登记一个由外部开发服务器提供的页面应用：

```json
{
  "name": "analysis",
  "type": "app",
  "entry": "http://127.0.0.1:5173/",
  "publicPath": "/micro/analysis/",
  "description": "分析页面"
}
```

这是本地联调示例，浏览器需要能访问对应开发服务器；正式部署应使用目标环境可访问的入口。前端构建的资源基路径也要与实际发布路径一致，否则 HTML 能加载，脚本、样式或图片仍可能请求到错误位置。

## 从资源登记到页面入口

需要作为页面打开时，再创建 UI 模型：

```json
{
  "path": "/analysis/overview",
  "title": "分析总览",
  "type": "micro",
  "microWebName": "analysis"
}
```

低代码 UI 模型加载时，通过 `microWebName` 查找资源，采用其 `entry`，入口为空时使用 `publicPath`。菜单引用 UI 模型的 `/analysis/overview` 路径；它不应直接引用资源包文件名。

因此，资源部署、路由登记和菜单编排是三个分别需要核对的环节。资源已经发布，只能说明文件可加载，不能说明菜单、接口或访问权限已经配置。

## 核心属性

| 属性 | 作用 | 说明 |
| --- | --- | --- |
| `name` | 微前端标识 | 注册、引用和部署资源时使用的名称。 |
| `type` | 微前端类型 | `app` 表示页面应用，`parcels` 表示视图，`library` 表示服务；默认 `app`。 |
| `entry` | 入口地址 | 浏览器加载该微前端的入口。 |
| `publicPath` | 静态资源基路径 | 确定脚本、样式和图片的加载路径。 |
| `packageName` | 内嵌资源包名 | JAR 元数据中用于定位打包前端资源的名称。 |
| `description` | 资源说明 | 低代码开发定义中的用途说明。 |
| `packagePath` | 开发包路径 | 创建或更新时引用上传的资源包；保存后记录为该微前端对应的 ZIP 包名。 |


## 资源包怎样交付

### 程序或插件内嵌资源

JAR 提供的微前端定义通过 `packageName` 定位内嵌资源包。运行时的资源部署服务读取包内容，再按 `publicPath` 发布静态资源。这种方式适合让前端资源随插件一起交付。

### 开发平台上传资源

低代码开发定义通过 `packagePath` 接收上传包，保存后记录为该微前端名称对应的 ZIP 包。更新时应同时检查定义和关联资源包，避免只提交入口变更而遗漏资源内容。

`packageName` 和 `packagePath` 属于不同来源对象，不能当作同一个必填字段。使用远程入口联调时也不要求伪造本地资源包。

## 与宿主协作

微前端可以使用独立技术栈构建页面，仍需遵循宿主的认证、路由、资源和接口约定。组件显示成功后，还要核对接口请求携带的身份、页面离开时的资源释放，以及多次进入页面是否产生重复订阅。

同一个应用可以同时使用 UI Schema 页面和微前端页面。结构化表单和列表可以继续使用 Schema，复杂交互交给微前端；业务对象、权限和外部服务调用的后端职责不因此改变。

## 常见问题

### 已上传资源包，为什么导航中没有新页面？

资源包不负责创建导航。检查 UI 模型是否引用微前端、菜单是否引用页面路由，以及该菜单是否进入模块编排并获授权。

### 页面 HTML 能打开，脚本却返回 404，先查哪里？

检查构建产物的资源基路径、模型的 `publicPath` 和静态服务中的实际目录是否一致，再检查入口地址与浏览器网络请求。

### 本地入口在别人电脑上能用吗？

`127.0.0.1` 指每个浏览器所在的本机。共享环境应填写其他使用者也能访问的服务地址。
