# 数据字典模型

数据字典模型维护一组具有稳定编码的选项。业务字段保存编码，页面展示对应文本；不同页面引用同一字典，就能使用一致的选项和含义。字典可以是平面列表，也可以组织成树。

## 编码与显示文本

字典项的 `code` 是业务数据中的实际值，`label` 是用户看到的名称。例如字段保存 `enabled`，界面显示“启用”。修改显示文本通常不需要修改业务数据；更换编码则会影响已有记录、查询条件和逻辑流中的判断。

字典名称用于选择整组值，字典项编码用于选择组内的一个值。不同字典可以使用相同编码，同一字典内应保持编码唯一。

```json
{
  "name": "availability",
  "title": "启用状态",
  "type": "enum",
  "group": "common",
  "editable": false,
  "treeMode": false,
  "items": [
    { "code": "enabled", "label": "启用", "order": 10 },
    { "code": "disabled", "label": "停用", "order": 20 }
  ]
}
```

这份定义提供两个可选值。它不会自动给某个业务字段赋值，也不会因为选择“停用”就执行停用动作；字段引用、默认值和业务处理需要分别配置。

## 字典类别

字典的 `type` 区分 `code_table` 代码表、`enum` 枚举值与 `state_table` 状态表。类别描述选项的用途，`treeMode` 则独立控制是否有父子层级。字典项编码由当前契约按字符串表达，不能将 `type` 填成 `String` 或 `Integer` 来选择编码类型。

## 平面字典与树形字典

平面字典适合状态、级别等互相并列的值。树形字典适合分类目录，`treeMode` 设为 `true`，通过 `parent` 或嵌套 `children` 表达层级。采用嵌套结构时，应让子项的父级编码与实际父项保持一致。

运行时管理服务会把树拆成可保存的字典项，再在查询时组装回树。层级关系只用于字典选项的组织，不会自动形成业务模型关系或部门层级。

## 开发定义与运行时维护

应用元数据和插件资源可以提供字典定义，运行时管理也可以维护允许编辑的字典。`editable` 决定运行时管理能力是否允许修改该字典及其字典项；它不等同于业务字段的可编辑权限。

产品固定值域适合随应用定义交付。需要使用方持续维护的选项应明确允许编辑，并约定维护职责。更改一个被多处引用的字典前，应检查业务字段、条件判断和报表中的编码引用。

## 核心属性

| 属性 | 作用 | 说明 |
| --- | --- | --- |
| `name` | 字典标识 | 运行时查询和字段引用使用的名称。 |
| `title` | 字典标题 | 开发界面和管理界面显示的名称。 |
| `type` | 字典类别 | `code_table` 代码表、`enum` 枚举值、`state_table` 状态表；不表示编码的数据类型。 |
| `group` | 字典分组 | 按业务用途组织字典。 |
| `editable` | 允许编辑 | 声明字典是否允许通过管理能力维护。 |
| `treeMode` | 树形模式 | 控制字典项是否采用父子结构。 |
| `items` | 字典项 | 保存字典编码、显示文本和排序等定义。 |

### 字典项

| 属性 | 作用 | 说明 |
| --- | --- | --- |
| `items[].code` | 选项编码 | 业务字段实际保存和引用的值。 |
| `items[].label` | 选项文本 | 页面向用户展示的文字。 |
| `items[].order` | 展示顺序 | 控制字典项的排序。 |
| `items[].parent` | 父项编码 | 树形字典中引用上级选项。 |
| `items[].children` | 子项集合 | 嵌套表达树形字典的下级选项。 |
| `items[].extraProps` | 扩展属性 | 保存颜色等由具体组件或业务约定消费的附加信息。 |


## 扩展信息与状态迁移

字典项的 `extraProps` 保存由控件或业务能力解释的附加信息，例如颜色。状态表的管理界面还提供 `stateTransition` 配置，定义放在 `extraProps` 内；每条迁移包含以下属性。

| 属性 | 含义 | 说明 |
| --- | --- | --- |
| `extraProps.stateTransition[].to` | 目标状态 | 引用同一字典的目标项编码。 |
| `extraProps.stateTransition[].condition` | 迁移条件 | 由消费状态迁移定义的能力解释。 |

字典只描述状态值和迁移约定。它不负责驱动审批实例、执行业务动作或保证某次写入符合状态机规则；需要限制状态变化时，应在对应的业务动作或流程中执行检查。

## 选择字典还是业务模型

字典适合值域有限、主要由编码和名称构成的选项。当数据需要独立字段、复杂关系、业务动作或精细权限时，应采用业务模型。不要把大量动态业务记录塞进字典项的扩展属性。

## 常见问题

### 改了字典文本，历史数据会失效吗？

只修改 `label` 时，记录中的编码保持原样，按当前字典解析的页面会显示新文本。需要保留历史显示快照的业务，应另外保存快照字段。

### 删除选项后，原来保存这个值的记录会自动更新吗？

不会。先处理历史值的替换、显示和查询兼容，再删除或迁移选项。

### 为什么运行时不能修改某个字典？

检查字典的 `editable` 和当前账号的管理权限。固定字典应在定义来源中修订，不能通过运行时维护绕过限制。
