# 字段类型

字段类型将一类字段的数据定义、输入控件、展示控件和默认校验组织在一起。业务模型选择字段类型、填写参数后，平台据此构建具体的数据字段与页面字段。同一套定义可以在多个业务模型中复用。

## 从类型定义到具体字段

字段类型由两部分配合工作：类型定义提供模板，字段实例提供参数。编译时先取 `defaultParams`，再用字段实例的参数覆盖同名值，最后解析数据类型、控件和主键生成器中的模板表达式。

以单行文本为例，长度参数可以同时约束数据字段的长度和输入框可输入的字符数。类型参数编辑器负责让开发者填写长度；真正参与编译的是参数值，参数编辑器本身不会代替数据字段定义。

下面是一份说明这种关联的字段类型定义：

```json
{
  "name": "shortText",
  "label": "短文本",
  "defaultParams": { "size": 60 },
  "dataType": { "type": "String", "size": "${size}" },
  "ui": {
    "input": { "type": "input-text", "maxLength": "${size}" },
    "display": { "type": "static-text" }
  },
  "paramsUiSchema": [
    { "type": "input-number", "name": "size", "label": "长度", "min": 1 }
  ]
}
```

不另传参数时，编译后的数据长度和输入上限均为 60；字段实例传入 `size: 120` 时，两处随之调整为 120。整段 `${size}` 表达式会保留数值结果的类型。

## 数据、页面和校验各负责什么

### 数据字段

`dataType` 是数据字段元数据模板，由数据模型能力解释其中的 `type`、长度或精度等属性。字段类型名称和底层数据类型名称属于不同层次，例如业务上的手机号类型可以落到字符串数据字段上。直接编写数据模型时，仍应遵循数据模型自己的字段类型契约。

### 输入与展示

`ui.input` 定义编辑时的控件，`ui.display` 定义只读展示。没有提供展示模板时，默认编译器会复制输入控件并标记为静态展示。两个模板均可引用字段参数。

`validations` 和 `validationErrors` 被放入控件模板，约束页面输入并提供提示文案。数据库可空性、唯一性以及后端业务校验仍需在数据字段和业务处理层分别定义，不能用页面校验替代。

### 主键

主键类型通过 `isPrimaryKeyType` 声明，并可提供 `primaryKeyGenerator`。选择主键类型时需要同时考虑底层数据类型与生成策略；已有数据和外部引用建立后，更换主键策略应按数据迁移评估。

## 核心属性

| 属性 | 作用 | 说明 |
| --- | --- | --- |
| `name` | 类型标识 | 业务模型字段选择该类型时使用的名称。 |
| `label` | 类型标题 | 字段类型列表和编辑器中的显示名称。 |
| `description` | 类型说明 | 解释字段语义及适用场景。 |
| `order` | 展示顺序 | 控制字段类型在选择列表中的排序。 |
| `isPrimaryKeyType` | 主键类型标记 | 声明该类型是否可用于主键。 |
| `primaryKeyGenerator` | 主键生成器 | 指定该类型采用的主键生成策略。 |
| `dataType` | 数据类型配置 | 描述底层数据类型及其参数。 |
| `ui` | 页面配置 | 定义该类型的默认输入组件和展示组件。 |
| `validations` | 校验规则 | 声明该类型的默认校验约束。 |
| `validationErrors` | 校验提示 | 为校验规则配置用户可见的错误文案。 |
| `paramsUiSchema` | 参数编辑器 | 定义字段类型参数的配置表单。 |
| `defaultParams` | 默认参数 | 编译时先采用的参数；字段实例传入的同名参数覆盖它。 |
| `source` | 定义来源 | 运行时记录的类型来源，用于追溯和管理。 |
| `sourceLocation` | 来源位置 | 记录定义文件或其他来源的位置。 |


## 定义来源与变更影响

类型目录汇总基座、插件以及应用提供的定义，`source` 和 `sourceLocation` 用来追溯最终类型的来源。这两个值由加载过程记录，编写定义时无需伪造。

多个字段会引用同一类型。修改通用类型的存储映射、参数名称或控件协议前，应检查已有字段参数是否仍可解析，以及已经落库的数据是否兼容。只对单个字段生效的限制，优先在该字段配置中调整；确实可复用的语义再沉淀为字段类型。

## 常见问题

### 配了参数编辑器，为什么模板解析仍然报错？

检查模板引用的每个参数是否都有值。`paramsUiSchema` 描述编辑表单，`defaultParams` 才是编译时直接合并的默认参数；两者应保持一致。数据类型模板的表达式求值为空会导致编译失败。

### 为什么编辑控件和列表展示长得一样？

检查是否提供 `ui.display`。省略时默认使用输入模板的静态形态；需要不同展示方式时，应明确配置展示模板。

### 字段类型里的校验可以阻止所有非法接口请求吗？

这里的控件校验主要服务页面输入。接口提交、逻辑执行和数据写入仍应执行各自的后端校验。
