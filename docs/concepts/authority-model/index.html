权限模型

权限模型把应用中的可访问能力命名为稳定的权限项，并关联接口、页面、菜单和可配置的数据访问范围。权限定义说明可以授予什么，角色或其他授权来源决定实际授予谁、授予多大范围；运行时再根据当前身份执行访问检查。

从权限定义到有效授权​

业务模型可以投影标准查询、新建、更新等权限，程序和插件也可以提供权限定义。定义进入权限目录后，授权管理将其赋给角色等主体，并按需要保存字段选择、数据范围等参数。

阶段保存或产生的内容需要核对
定义权限权限全名、关联目标、可配置的访问控制维度是否关联实际接口或业务能力。
配置授权权限引用及具体访问控制参数哪些身份取得该权限、范围是否合适。
运行时检查当前身份的有效权限及行列约束调用链是否真正使用平台授权和数据访问机制。

只声明权限不会给用户授权，只给菜单授权也不会代替接口和数据检查。自定义处理器应沿用正式权限链路，避免出现页面有控制、直接请求却可绕过的情况。

四类访问目标​

菜单与页面​

menuItems 引用菜单全名，控制导航入口；uiViews 引用页面路径，描述页面访问。菜单隐藏后，页面地址和接口仍然存在，需要由相应规则继续保护。

菜单的父子结构不表示权限自动继承。获得某个页面入口的权限，也不代表获得同组所有入口；为了展示子菜单而保留祖先分组，同样不表示祖先下的其他功能都获授权。

接口与业务动作​

apis 关联接口标识。HTTP 方法也是标识的一部分，应使用接口目录中的准确值。业务动作还可以有自己的权限要求，处理器调用动作时继续进入动作运行时检查。

例如，独立权限可以关联一个查询接口和对应入口：

{
  "fullName": "analysis.read",
  "title": "查看分析",
  "apis": ["GET /analysis/summary"],
  "uiViews": ["/analysis/overview"],
  "menuItems": ["analysis.overview"],
  "delegable": false
}

这份定义要求目标接口、页面和菜单已经存在。它没有把权限授予任何角色，也没有实现查询的数据范围。

行权限与列权限​

行权限限制可以访问哪些记录，列权限限制可以读取或写入哪些业务字段。业务模型的查询、更新、删除等操作分别消费对应访问约束；接口鉴权通过后，仍需执行这些检查。

accessControlDefine 描述授权界面可配置的维度，实际授权参数保存本次字段选择和范围条件。仅列出受控字段或过滤维度，不等于已经为某个角色施加限制。

字段选择​

commonFields 是公共字段，controlledFields 是可以选择授权的字段。实际字段选择使用 $fieldControl；权限解释器结合定义计算允许和禁止访问的字段。

完整授权与带约束授权应分清。当前 RBAC 中没有保存约束参数的完整授权，不会仅因为定义列出了受控字段就自动收紧范围。涉及敏感管理的能力应同时使用对应授权入口的显式选择策略，并检查最终字段约束。

记录过滤​

filterDefine 描述可配置的数据范围参数和编辑表单。运行时由访问控制过滤器解析参数，并与调用方自己的查询条件一起限制访问。调用方不能通过提交更宽的查询条件扩大授权范围。

过滤参数必须有有效解析器，不能添加一个无人解释的自定义键期待自动生效。当前实现对未被解析的访问控制参数会拒绝访问。

核心属性​

属性作用说明
fullName权限全名授权引用的稳定标识。
name权限名称从权限全名末段计算得到的只读名称。
parent上级权限从权限全名推导的只读父级标识。
level权限层级根据父级关系计算得到的层级。
title权限标题授权和管理页面使用的显示名称。
apis接口关联列出该权限项关联的接口标识。
uiViews页面关联列出该权限项关联的页面路径。
menuItems菜单关联列出该权限项关联的菜单标识。
order展示顺序运行时权限接口提供的排序值。
delegable允许委托声明该权限是否可以纳入委托凭据的授权范围。
accessControlDefine访问控制定义描述该权限可使用的数据过滤与字段控制参数。

访问控制参数​

属性作用说明
accessControlDefine.canControlFields字段控制开关声明该权限是否支持字段级控制。
accessControlDefine.fieldSelectionRequired要求显式字段选择控制字段约束是否要求明确选取；具体授权入口仍需执行对应策略。
accessControlDefine.commonFields公共字段列出访问控制中使用的公共字段。
accessControlDefine.controlledFields受控字段列出允许配置访问限制的字段。
accessControlDefine.filterDefine过滤定义声明该权限可配置的数据过滤参数。

字段描述​

commonFields[] 和 controlledFields[] 中的每项使用相同的字段描述。

属性含义说明
name字段名对应业务字段的逻辑名称。
label字段标题授权界面显示的名称。
type字段类型供授权界面解释字段。
description字段说明解释字段含义与授权影响。

过滤维度定义​

以下字段位于 accessControlDefine.filterDefine[] 中。

属性含义说明
name参数标识授权参数使用的名称。
label显示标题范围配置界面显示的名称。
description参数说明解释范围的含义。
dataType参数类型用于解释配置值。
originalFieldType来源字段类型关联原业务字段的类型。
originalFieldName来源字段名称关联原业务字段名称。
settingSchema配置表单输入该过滤参数使用的 UI Schema 列表。
extraProps扩展属性由相应解析器消费，JSON 中按属性名展开。

实际访问约束​

这些是授权解释后的运行时结果，与静态权限定义分开。

属性含义说明
allowedFields允许字段当前操作允许访问的字段，* 表示全部。
disallowedFields禁止字段当前操作明确不能访问的字段。
filters记录过滤已解析的数据范围条件。

权限层级、模块编排与委托​

权限全名以点分层，例如 analysis.read 的默认父级是 analysis。模块编排可以组织权限树的显示、归属和排序，实际关联的接口、页面与访问控制仍来自权限本身。父级占位帮助组织目录，不能代替具体能力授权。

delegable 默认关闭。只有执行链能够持续承接凭据约束的权限才能声明可委托；开启后也不等于给外部应用直接授权，还需要凭据授权范围和后续访问约束共同生效。

组织信息提供员工归属和岗位事实，角色表达授权组合。某人属于部门、担任岗位，与他是否具有某个操作权限是不同判断，需由相应授权机制连接。

常见问题​

为什么角色里有权限，页面仍无数据？​

先检查权限关联的接口是否正确，再检查查询的行范围、列范围、当前身份及组织上下文。权限项存在不表示记录一定落在授权范围内。

为什么页面按钮隐藏了，接口还能调用？​

按钮和菜单可见性不等于后端授权。检查接口与业务动作的权限要求，确保直接请求同样经过正式检查。

给父权限授权会自动得到所有子权限吗？​

不要依靠树形层级推断授权。应核对当前身份实际取得的权限项和目标接口、页面、菜单关联，明确授予所需能力。
