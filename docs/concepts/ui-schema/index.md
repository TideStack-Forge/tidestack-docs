# UI Schema 模型

UI Schema 用组件树描述页面：有哪些内容、如何布局、从哪里取数，以及用户操作后发生什么。表单、列表、详情、弹窗和看板都可以由这类声明式定义组合而成，再由前端基座中的 PrismUI 渲染。

页面的结构与交互保存在 JSON 中，可视化编辑和代码编辑维护同一份定义。组件的完整用法、属性和示例见 [PrismUI 官方文档](https://prismui.io/docs/zh-CN/docs/index)。

## 从一份定义看页面结构

下面是一份独立的 UI Schema 资源。它包含一个表单：填写显示名称，开启通知后再显示邮箱输入框。

```json
{
  "name": "settings.profile",
  "title": "资料与通知设置",
  "description": "演示表单字段、初始数据和条件显示。",
  "schema": {
    "type": "page",
    "title": "资料与通知设置",
    "body": [
      {
        "type": "form",
        "id": "profile-form",
        "title": "基本设置",
        "data": {
          "displayName": "示例用户",
          "receiveNotice": false
        },
        "body": [
          {
            "type": "input-text",
            "name": "displayName",
            "label": "显示名称",
            "required": true
          },
          {
            "type": "switch",
            "name": "receiveNotice",
            "label": "接收通知"
          },
          {
            "type": "input-email",
            "name": "email",
            "label": "通知邮箱",
            "visibleOn": "${receiveNotice}",
            "requiredOn": "${receiveNotice}"
          }
        ],
        "actions": [
          { "type": "reset", "label": "重置" }
        ]
      }
    ]
  }
}
```

外层的 `name`、`title` 和 `description` 用于标识、管理这份资源，`schema` 才是交给渲染器的组件树。树中的 `page` 容纳 `form`，表单再容纳三个字段；表单的 `data` 提供初始数据，字段的 `name` 把输入绑定到对应数据项。

这个例子只处理页面内的数据，没有配置保存接口。需要持久化时，还要为表单配置提交接口，并由后端执行校验和写入。增加一个输入框，不会自动给业务模型或数据模型增加字段。

## 页面入口与 Schema 资源

[UI 模型](../ui-model/)负责页面路径与实现方式，UI Schema 负责页面内容。独立创建一份 Schema 后，它已经可以被引用，但还没有因此成为一个页面路由或菜单入口。

| 标识 | 所属对象 | 用途 |
| --- | --- | --- |
| `name` | UI Schema 资源 | 标识一份可管理、可引用的页面定义。 |
| `path` | UI 模型 | 定义用户访问的页面路径。 |
| `schemaId` | UI 模型或引用组件 | 指定需要加载的 Schema 资源路径。 |
| `id` | 组件节点 | 定位当前页面中的组件，供事件动作调用。 |
| `name` | 表单项等组件 | 绑定数据字段；不等同于 Schema 资源名称。 |

例如，下面的 UI 模型把 `/settings/account` 页面指向前面的资源：

```json
{
  "path": "/settings/account",
  "title": "资料与通知设置",
  "type": "amis",
  "schemaId": "/settings/profile"
}
```

`amis` 是当前平台中 UI Schema 页面使用的实现类型值。`schemaId` 不填写时，平台默认按 UI 模型的页面路径查找 Schema；两个路径不同时，需要显式指定。

资源名称会转换为查找路径：`settings.profile` 对应 `/settings/profile`，点分名称的各段还会转为短横线命名；已经使用 `/settings/profile` 这样的路径名称时，按路径查找。资源路径与浏览器页面路径可以相同，也可以分别维护。

菜单通过页面路径提供入口，权限控制页面和业务能力的访问。Schema 中的条件显示仅控制界面呈现，不能替代后端授权。

## 定义来源与覆盖

业务模型的视图投影、应用内单独维护的页面、插件提供的页面，都可以成为 UI Schema 的来源。

| 来源 | 如何形成 | 适合的调整方式 |
| --- | --- | --- |
| 业务模型投影 | 根据字段、视图和动作等定义形成标准列表、表单或详情。 | 通用页面规则优先在业务模型中调整；需要独立定制布局和交互时维护相应 Schema。 |
| 应用元数据 | 在应用的 `ui-schema` 目录中保存 `.ui-schema.json` 定义。 | 使用开发平台的可视化或代码编辑器维护。 |
| 程序或插件内嵌资源 | 随模块、插件提供 Schema 定义。 | 在正式资源来源中维护，或在应用层提供同路径定制。 |
| UI 模型内嵌定义 | UI 模型的 `schema` 属性直接提供页面内容。 | 修改对应 UI 模型中的内嵌定义。 |
| 运行时定制 | 加载 UI Schema 实时管理模块后，以数据库记录维护启用的页面定义。 | 按资源路径管理运行环境中的定制。 |

运行时按资源路径向 Schema 提供者查找定义，同路径命中优先级更高的来源后，就使用该来源提供的 Schema。在当前内置提供者中，启用的数据库定制优先于应用元数据，应用元数据优先于程序内嵌资源；业务模型投影和 UI 模型内嵌定义也通过相应提供者参与查找。

这种覆盖以**整份 Schema** 为单位，不会自动把新旧两份组件树逐字段合并。维护完整定制副本后，下层页面后来新增的组件和交互也需要在该副本中评估、同步。

## 资源属性与组件结构

### 资源属性

| 属性 | 作用 | 说明 |
| --- | --- | --- |
| `name` | 资源名称 | 用于管理及定位定义，加载时转换为 Schema 资源路径。 |
| `title` | 备注名称 | 用于开发管理和检索；不等同于组件树中的页面标题。 |
| `description` | 资源说明 | 描述页面用途及适用场景。 |
| `schema` | 组件树 | 描述要渲染的页面或组件内容。 |

资源外层的 `title` 不会自动成为页面上显示的标题。示例中两处标题相同，是因为同时填写了资源 `title` 和 `schema.title`。

### 组件通用属性

组件树通过 `type` 选择组件，其他属性按该组件支持的配置解释。容器中的 `body`、表格中的 `columns` 和表单中的 `actions` 各有职责，不能任意互换。

| 属性 | 作用 | 说明 |
| --- | --- | --- |
| `type` | 组件类型 | 例如 `page`、`form`、`crud`、`input-text` 或 `button`。 |
| `id` | 组件标识 | 用于事件动作定位；同一交互范围内应避免重复。 |
| `name` | 数据绑定或组件名称 | 表单项通常用它指定字段，其他组件按自身规则解释。 |
| `className` | 样式类 | 为当前组件附加样式。 |
| `visible` | 静态可见性 | 控制组件是否显示。 |
| `hidden` | 静态隐藏 | 控制组件是否隐藏。 |
| `visibleOn` | 条件显示 | 根据当前数据上下文中的表达式计算可见性。 |
| `hiddenOn` | 条件隐藏 | 根据表达式计算是否隐藏。 |
| `onEvent` | 事件配置 | 定义组件事件触发后的动作。 |

### 容器与内容属性

以下属性由支持它们的组件使用，并非所有组件都具有这些区域。

| 属性 | 作用 | 说明 |
| --- | --- | --- |
| `title` | 组件标题 | 用于页面、表单、弹窗等组件的标题区域。 |
| `body` | 主体内容 | 容纳子组件，形成页面的父子结构。 |
| `aside` | 侧栏内容 | 在页面组件中安排侧栏。 |
| `toolbar` | 工具栏内容 | 在页面等组件支持的工具栏区域安排操作。 |
| `actions` | 操作区 | 例如表单或弹窗底部的按钮集合。 |
| `columns` | 列定义 | 描述列表或表格的字段、标题和单元格展示。 |
| `bodyClassName` | 主体样式类 | 为支持该属性的组件主体区域设置样式。 |

## 数据绑定与表单校验

页面数据通常来自初始数据、路由参数、接口响应和用户输入。表单、列表等数据容器会组织各自的上下文；表达式在所在组件的数据范围内取值。把组件移动到另一个容器后，即使表达式文本未变，可取得的数据也可能发生变化。

`${displayName}` 读取当前上下文中的字段，`${receiveNotice}` 可以用于条件显示。路由路径参数可通过 `params` 访问，查询参数可通过 `query` 访问；平台还提供 `SystemConfig` 和 `SystemContext`，分别承载应用配置及当前用户、组织架构、权限等上下文。组件内部的数据与路由参数重名时，应优先使用明确的对象路径。

### 表单项属性

| 属性 | 作用 | 说明 |
| --- | --- | --- |
| `name` | 字段名称 | 决定输入值在表单数据中的位置，应与接口约定的参数名称一致。 |
| `label` | 字段标题 | 显示给用户的名称。 |
| `value` | 字段初始值 | 为字段提供初始配置；不表示数据已保存到后端。 |
| `placeholder` | 输入提示 | 提示用户可以填写的内容。 |
| `description` | 字段说明 | 补充填写要求和业务含义。 |
| `required` | 必填 | 声明固定的必填要求。 |
| `requiredOn` | 条件必填 | 根据表达式决定是否必填。 |
| `validations` | 校验规则 | 声明组件支持的格式、范围等规则。 |
| `validationErrors` | 校验提示 | 为相应校验规则设置错误消息。 |
| `disabled` | 静态禁用 | 控制用户是否能编辑该字段。 |
| `disabledOn` | 条件禁用 | 根据表达式决定是否允许编辑。 |
| `validateApi` | 远程校验 | 通过接口检查字段值，使用方式取决于组件。 |

前端校验用于及时反馈，后端仍需验证必填项、业务规则和访问权限。隐藏或禁用字段不会自动改变后端规则，也不应据此假定字段值已从提交数据中移除。

## 数据请求与提交

表单的 `initApi` 用于读取初始数据，`api` 用于提交；列表组件的 `api` 则通常用于加载列表。相同属性在不同组件中的触发时机和结果处理，应结合组件定义判断。

| 属性 | 作用 | 说明 |
| --- | --- | --- |
| `data` | 初始数据 | 页面、表单等数据容器中声明的初始数据。 |
| `initApi` | 初始化接口 | 加载页面或表单的初始数据。 |
| `api` | 数据接口 | 按组件用途执行查询、提交或其他请求。 |
| `source` | 数据来源 | 在选择器等组件中配置选项来源，或在相应组件中指定远程内容。 |

接口可以写成简写字符串，也可以写成对象。对象形式适合明确维护方法、参数与返回值映射。例如，表单的 `api` 可以配置为：

```json
{
  "method": "post",
  "url": "/api/example/profile",
  "data": {
    "displayName": "${displayName}",
    "receiveNotice": "${receiveNotice}",
    "email": "${email}"
  }
}
```

这里的 `/api/example/profile` 是示意地址，使用时应替换为已有接口。页面通过接口调用后端能力，后端再执行业务动作、逻辑流或数据访问；Schema 本身不直接读写数据库。

### 接口配置属性

| 属性 | 作用 | 说明 |
| --- | --- | --- |
| `method` | 请求方法 | 例如 `get`、`post`、`put` 或 `delete`。 |
| `url` | 请求地址 | 可以按上下文引用参数。 |
| `data` | 请求数据映射 | 声明发送给接口的数据，与容器上的初始 `data` 所处层级不同。 |
| `dataType` | 请求数据格式 | 指定请求数据的编码方式，按接口要求配置。 |
| `headers` | 请求头 | 配置该请求需要的附加头。 |
| `sendOn` | 发送条件 | 根据表达式决定是否发送请求。 |
| `requestAdaptor` | 请求适配 | 发送前按需调整请求。 |
| `adaptor` | 响应适配 | 按需转换响应，使其满足组件要求。 |
| `responseData` | 响应数据映射 | 把接口结果映射为组件使用的字段。 |
| `responseType` | 响应类型 | 声明需要按何种类型处理响应。 |
| `replaceData` | 数据替换策略 | 控制相应接口结果是否替换已有数据。 |
| `cache` | 请求缓存 | 配置该请求的缓存行为。 |
| `autoRefresh` | 自动刷新 | 控制接口配置支持的自动刷新行为。 |
| `trackExpression` | 请求跟踪表达式 | 在相关值变化时参与请求刷新判断。 |
| `qsOptions` | 查询参数序列化 | 配置查询字符串的序列化方式。 |

请求成功后页面没有数据时，先检查返回结构与组件要求是否一致。例如列表需要记录集合，表单需要字段对象；接口返回了数据，不代表组件一定能按预期取到它。能通过字段映射解决的结构差异，优先使用 `responseData`。

## 事件与交互动作

`onEvent` 把组件事件与动作关联起来。例如，按钮点击后显示一条提示：

```json
{
  "type": "button",
  "label": "查看当前填写",
  "onEvent": {
    "click": {
      "actions": [
        {
          "actionType": "toast",
          "args": {
            "msgType": "info",
            "msg": "当前填写：${displayName}"
          }
        }
      ]
    }
  }
}
```

把按钮放在能够访问表单数据的范围内，才能取得 `displayName`。需要修改其他组件时，通过目标组件标识定位；对话框、页面跳转、请求和数据更新则使用相应动作。

### 事件动作属性

以下属性位于 `onEvent.<事件名>.actions[]` 中。

| 属性 | 作用 | 说明 |
| --- | --- | --- |
| `actionType` | 动作类型 | 选择提示、请求、数据更新、组件调用或平台扩展动作等能力。 |
| `componentId` | 目标组件 ID | 通过组件 `id` 定位操作对象。 |
| `componentName` | 目标组件名称 | 在支持按名称定位的动作中指定目标。 |
| `args` | 动作参数 | 保存当前动作约定的参数。 |
| `data` | 动作数据 | 为动作提供需要传递的数据。 |
| `dataMergeMode` | 数据合并方式 | 指定动作数据的合并策略。 |
| `expression` | 执行条件 | 根据表达式决定是否执行该动作。 |
| `outputVar` | 输出变量 | 保存动作结果，供后续处理引用。 |
| `preventDefault` | 阻止默认行为 | 按事件和动作支持情况控制默认处理。 |
| `stopPropagation` | 停止传播 | 按事件和动作支持情况控制事件传播。 |

组件支持哪些事件、动作接收哪些参数，需要分别查阅。流程中的“保存成功后刷新列表”也应绑定到真正的提交成功事件，不能只绑定按钮点击，否则接口失败时仍可能执行后续界面操作。

## 页面组合与扩展

完整页面和可复用片段都可以保存为 UI Schema。平台的弹窗、抽屉支持通过 `schemaId` 引用已有 Schema，也支持通过 `url` 引用页面路由，再按路由解析实际内容。前者直接选择内容资源，后者通过页面入口复用实现。

字段控件与格式展示由相应组件承接；平台组件库可以注册新的渲染器，使自定义 `type` 进入同一套声明式页面机制。需要独立构建、独立发布或复杂专用交互时，可以使用[微前端模型](../micro-web-model/)，再通过 UI 模型提供页面入口。

复用片段时，需要明确传入哪些数据、触发哪些事件、由谁负责请求和提交。把接口请求、业务规则和组件状态都隐藏在一段大脚本中，会使调用方难以判断依赖和失败行为。

## 常见问题

### 新建 Schema 后，为什么没有页面入口？

Schema 资源描述内容，页面路径由 UI 模型定义，菜单再引用页面路径。检查 UI 模型是否存在，`schemaId` 是否指向这份资源，以及菜单和权限是否正确。

### 为什么修改资源标题，页面标题没有变化？

资源外层的 `title` 用于管理，`schema.title` 是页面组件标题，UI 模型的 `title` 还用于页面入口和标签等场景。应修改实际需要显示的那一处。

### 为什么表达式在预览中取不到值？

检查表达式所在的数据范围，以及预览是否提供了所需的路由参数、接口结果或父组件数据。预览缺少运行数据时，还应进入实际页面验证。

### 为什么修改底层页面后，运行环境仍显示旧内容？

检查同路径是否存在应用定制或启用的运行时定制。高优先级来源会覆盖整份 Schema，底层定义的修改不会自动合并进定制副本；同时确认元数据已更新并重新加载页面。

### UI Schema 与 JSON Schema 有什么区别？

UI Schema 描述如何组织、展示和操作界面；JSON Schema 描述数据结构与校验约束。表单可以同时涉及两者，但用途不同，不能把数据校验定义直接当作完整页面使用。
