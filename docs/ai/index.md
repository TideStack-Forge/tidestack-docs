# AI 入口

把潮汐栈手册交给 AI 助手后，可以让它解释模型、拆解业务需求、编写元数据或实现扩展。本栏目说明如何提供上下文、选择文档和验证交付结果，适用于 IDE 助手、coding agent 和对话式 AI。

## 把手册提供给 AI

按助手能够读取的内容选择一种方式：

| 使用环境 | 提供什么 | 接下来做什么 |
| --- | --- | --- |
| 助手能够访问手册站点 | [llms.txt](pathname:///llms.txt)；需要更多入口时提供 [llms-full.txt](pathname:///llms-full.txt) | 让助手按索引读取当前任务相关的页面 |
| 助手能够读取本地 Handbook 仓库 | 仓库根目录的 `llms.txt` 和本栏目 | 让助手按索引读取本地 Markdown 与 Schema |
| 助手只能读取对话内容 | 从[任务路由](./routing-hints.md)选出相关页面，粘贴必要正文与版本信息 | 补充具体需求、现有定义和错误信息 |

两个 `llms` 文件都是文档索引，`llms-full.txt` 提供更详细的路由说明，并非全站正文。索引中的 `docs/...`、`openapi/...` 等路径相对于 Handbook 仓库根目录；其中 Schema 等仓库资产不等同于站点下载地址。

如果助手已配置 Context7 或 MCP，可按[知识来源与工具边界](./reference-sources.md)使用已有能力。本栏目不提供可直接连接的潮汐栈 MCP 服务地址，也不假定当前环境已接入这些工具。

## 描述一次任务

提供目标平台版本、目标应用或模块、业务行为和验收要求。修改已有项目时，同时指定工作区，并让助手先读取该项目的开发约定和现有实现。

下面的模板可复制后填写：

```text
请依据潮汐栈 Handbook 完成以下任务：

平台版本：<目标平台版本>
目标位置：<工作区、应用或模块>
业务需求：<谁在什么条件下，需要完成什么操作>
现有实现：<相关模型、页面、接口或扩展；没有则说明>
验收要求：<成功、失败和无权限时分别应看到什么结果>

先从 AI 入口的任务路由选择相关文档，再检查目标项目的约定和已有实现。
优先复用业务模型及正式扩展点，保留 ouroboros 运行时标识。
修改前说明实现位置与必要假设；完成后列出改动和实际验证结果。
缺少版本依据、关键业务规则或执行环境时，明确说明并询问。
```

## 选择下一步

| 当前需要 | 阅读 |
| --- | --- |
| 根据需求找到最少必要文档 | [按任务选择上下文](./routing-hints.md) |
| 组织一次模型、页面、流程与实现的 AI 开发任务 | [用 AI 完成功能开发](../fusion-development/ai-assisted-development.md) |
| 实施业务功能、元数据、扩展或排障任务 | [任务执行与验收](./task-recipes.md) |
| 判断文档、Schema、项目文件和工具各自能证明什么 | [知识来源与工具边界](./reference-sources.md) |
| 处理 TideStack 与 Ouroboros 的名称 | [术语与兼容命名](./terminology.md) |

手册中的版本声明以具体专题为准。例如，低代码开发栏目按 `2.1.0-SNAPSHOT` 说明，API 参考的默认版本为 `2.0.0-rc.1-SNAPSHOT`，其中部分专题另有声明。让 AI 生成代码或元数据前，必须核对目标版本，不能把不同版本的字段和 API 直接拼接使用。
