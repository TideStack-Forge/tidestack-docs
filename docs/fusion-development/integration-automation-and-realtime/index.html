集成、自动化与实时能力

集成任务需要同时明确触发、处理和结果：谁发起、输入来自哪里、业务状态如何改变，以及用户如何得知结果。本页说明如何组合平台能力，以及需要新适配时应使用的扩展入口。

先确定完整调用链​

向 AI 提供目标应用与版本、已有接口和流程、脱敏协议、输入输出样例，以及超时、重复请求和失败时的预期结果。先核对已有定义，再列出要调整的配置、流程和适配实现。

业务需要已有入口确需扩展时使用
定时或延迟触发业务处理Java 定时方法，或计划任务调用逻辑流Scheduler、ScheduleTaskProvider 与现有聚合机制
异步投递和消费事件Java 发送与消费，或消息模型与流程MQBridge 及正式中间件适配
调用外部 HTTP 服务Java 或流程调用 RPC，或已有 Java 客户端现有接口无法表达的认证或协议适配
向在线页面反馈业务状态WebSocket 发送和订阅现有发送、鉴权及通道拦截扩展点

Java 直接开发见 MQ、计划任务与 RPC。配置操作见 集成与定时自动化。连接地址、凭据和开关使用已有配置机制。

计划任务：从触发到业务结果​

调度负责触发，逻辑流或业务服务负责实际处理。Java 方法可用 Spring 定时任务；需要平台调度逻辑流时，先定义稳定任务名、触发时间、流程名和输入数据，再配置任务或调用 Scheduler。

  • 周期任务：开发平台“计划任务”配置 Quartz Cron；程序侧使用 scheduleCron 等已有接口。
  • 一次性任务：通过 scheduleOnce 的时间或延迟参数调度，不把一次性需求伪装成周期任务。
  • 新增定义来源：实现 ScheduleTaskProvider.getAllScheduleTask()，按当前机制注册，由 ScheduleTaskIntegrator 聚合。

运行时已提供默认聚合逻辑。新增来源优先加入 Provider，不再维护另一份任务注册表或调度器。需要替换聚合策略时，先核对目标版本的装配入口和默认行为。

验证时，记录任务名、预计和实际触发时间、调用输入及最终业务状态。覆盖重复注册、执行失败和实例重启；任务恢复能力以实际调度后端和配置为准，不根据“已注册”推断已经成功执行。

外部接口：确认请求与响应映射​

先复用外部接口模型和已有认证方式，明确请求方法、参数、响应、错误与超时。AI 生成映射或流程时，提供真实脱敏样例，核对成功和失败响应是否走向正确分支。

只有现有模型无法承载的协议或认证部分进入适配实现。业务动作继续调用同一能力入口，凭据由环境配置提供。验证应包含实际请求、外部响应和本地状态，避免把 HTTP 请求成功等同于业务成功。

消息队列：从投递到消费结果​

通过 MQBridge 和现有 producer / consumer 抽象接入消息。Java 消费者直接注册 Handler，低代码消费者通过消息模型和逻辑流，二者沿用绑定配置；新增中间件才实现相应适配。

  1. 明确消息结构、业务标识、目标绑定及消费处理流程。
  2. 让 AI 对照已有 producer / consumer 实现调整配置或适配，补齐注册与必要元数据。
  3. 发送带可追溯标识的测试消息，分别确认发送、入队、消费和业务状态。
  4. 按目标中间件约定验证消费失败、重试和重复投递。

消息消费与业务写入之间需要明确幂等规则。不要在业务模块另建 RabbitMQ 客户端绕过 MQBridge，否则平台的绑定、配置和生命周期无法统一管理。

WebSocket：推送状态并恢复页面​

业务服务先完成状态更新和授权，再通过已有发送接口推送事件。前端连接 /websocket/stomp，订阅与后端发送语义一致的目的地。

契约要明确的内容
接收范围广播、用户或会话级发送，允许哪些用户订阅
事件内容业务标识、状态及页面更新所需字段
页面行为收到事件后直接展示还是重新查询真实状态
恢复方式断线、重连和漏收事件后如何恢复服务端状态

沿用连接鉴权、通道拦截和会话管理。前端验证未登录、无权限、断线重连和重复消息；不要把收到一条推送作为数据库更新成功的唯一依据，也不依赖实时通道保证只投递一次。

需要新协议、网关或连接治理时，才扩展实时通信底座，并验证与已有授权及会话机制一致。

组合异步处理与页面反馈​

下面是一种按需组合的路径；同步调用或简单定时任务不必增加消息队列和推送：

Scheduler 触发 → 逻辑流 / 业务服务创建任务
→ MQ 消费处理 → 业务状态落库 → WebSocket 通知页面
→ 页面展示或查询最终状态

让 AI 在各阶段保留可追溯的业务标识，并明确每一阶段失败时由谁重试、是否允许重复处理、用户看到什么。为正常、超时、消费失败和重复请求分别给出预期状态。

验证、排查与交付​

观察到的偏差先收集的证据
未触发任务定义、注册结果、时区和运行实例
外部调用失败请求映射、目标地址、脱敏响应和超时日志
已投递但未完成业务消息标识、绑定、消费日志和实际数据
业务完成但页面未更新发送范围、订阅目的地、连接状态和前端请求
重复执行或写入触发记录、投递记录、重试与幂等判断

按最早偏离预期的阶段修复，再复验下游结果。交付配置、流程、适配产物、兼容版本及实际验证记录，说明尚未覆盖的中间件或恢复场景。
