# 插件扩展

插件扩展为平台增加可重复使用的能力，例如组件、逻辑流节点、上下文对象、字段类型、模型插件、存储适配与认证方式。扩展实现和注册完成后，由应用、模型或流程按稳定契约引用。

“扩展”描述复用目的，不意味着所有能力都使用 Java SPI。前端有组件注册与清单，后端有 SPI、Spring Bean、模型描述符及其他正式装配入口。

| 方向 | 内容 |
| --- | --- |
| [前端](./frontend/) | 带 manifest 的平台组件库、普通组件包 |
| [后端](../../guide/advance/extend-backend/) | 节点、上下文、字段、脚本语言、模型插件、权限、认证及基础能力适配 |

单个应用的页面与服务实现分别见 [前端开发](../frontend-extension-paths)和 [后端开发](../backend-development/)。插件也可以随应用交付；是否复用取决于契约与使用范围，不取决于是否单独建仓库。

## 实现前确定契约

明确使用者、稳定名称、参数、结果、配置、权限、依赖与兼容版本。让 AI 读取接口、注册机制及同类实现，生成代码时同时处理清单、注册文件和使用样例。

## 交付与验证

后端按 [扩展包指南](../backend-extension-packages)打包，前端按所属组件教程安装。分别验证实现行为、产物发现以及真实使用入口；清单出现、Bean 存在或 SPI 可发现都不能单独证明业务可用。

为依赖方交付版本、使用样例、升级影响和恢复步骤。新增扩展应进入已有加载与执行链路，不再维护第二套模型中心、权限表或组件加载器。
