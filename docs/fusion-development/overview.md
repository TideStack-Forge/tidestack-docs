# 融合开发总览

融合开发不是另一套应用架构。扩展代码必须接入平台的模型、页面、接口、权限和运行时装配机制。

## 标准流程

1. 使用 [平台能力地图](../reference/platform-capability-map) 确认没有现成能力。
2. 使用 [判断表](./when-to-use-code) 确认需求属于可复用程序能力，而不是一次配置。
3. 在 [扩展点总表](./extension-points) 中选择唯一扩展点。
4. 实现最小能力并完成测试。
5. 通过扩展包、微前端或平台组件库交付。
6. 在目标应用中安装并通过模型或配置引用。
7. 验证卸载或回滚后，平台主线仍可恢复运行。

## 前端扩展边界

| 需求 | 扩展方式 |
| --- | --- |
| 独立复杂页面 | 微前端页面 |
| 替换顶栏、侧栏或登录页 | 布局组件或登录页微前端 |
| 多个 Schema 页面复用组件 | 组件库 |
| 跨应用安装、卸载和版本治理 | 平台组件库 |

## 后端扩展边界

| 需求 | 扩展方式 |
| --- | --- |
| 新字段语义 | 字段类型扩展 |
| 新公式或取值能力 | 表达式上下文扩展 |
| 新脚本对象 | 脚本上下文扩展 |
| 新编排节点 | 逻辑流节点扩展 |
| 多项 Bean、SPI 和资源组合交付 | 后端扩展包 |
| 需要开发态管理页面和元数据 | `*-dev` 开发模块 |

## 验收

- 扩展使用正式 Registry、SPI 或自动配置入口。
- 安装、升级、卸载和回滚步骤明确。
- 扩展失败不会绕过权限或破坏其他应用。
- 兼容版本和第三方依赖已经声明。
- 业务人员仍能通过平台配置消费该能力。
