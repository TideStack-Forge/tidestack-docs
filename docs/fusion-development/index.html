融合开发

融合开发让业务模型、页面、流程和代码共同构成一个应用。你可以在开发平台或 IDE 中维护模型，用 Java 实现业务服务，用微前端定制交互，也可以让 AI 协助完成这些工作。它们使用同一套模型、权限和运行机制。

第一次开发时，先选定工程模式，让应用和运行环境启动起来，再完成一项具体功能。已有项目只需进入对应技术专题；按需求查找入口可使用 开发任务导航。

工程准备​

先确定谁提供启动程序、模型和代码放在哪里、最终交付哪些产物。由开发平台创建应用并补充代码时，可从标准基座扩展模式开始；已有 Spring Boot 工程需要自行装配基座时，选择内嵌基座模式。

要完成的事指导文档
比较启动入口、依赖和交付责任选择工程模式
使用标准基座，准备应用元数据、扩展包与前端工程标准基座扩展模式
建立自己的启动程序并装配基座能力内嵌基座模式
安装 IDE 工具，配置模型编译、依赖过滤与校验开发工具
创建并装配后端业务 JAR后端扩展包
确认模型源码、构建输出与 JAR 内资源目录模型资源与打包

开始开发​

先选一个具体业务行为，找到现有模型、页面和接口，确认所需改动与验收结果。首次实现宜先贯通一个可操作的入口，再逐步增加规则和交互。

当前任务阅读入口
了解模型与代码怎样配合完成应用融合开发总览
将需求拆成模型、页面、流程和代码的改动从需求确定实现范围
从数据模型、Java 接口做到页面、菜单和角色授权完成第一个融合开发功能，含完整示例工程
已有明确需求，寻找适合的实现方式开发任务导航
让 AI 读取已有资产、完成修改并验证用 AI 完成功能开发

后端开发​

从已有数据和普通 Service 入手，再把业务行为接入动作、流程和接口。需要消息处理或后台执行时，继续使用消息与任务能力。

在 Java 中读写已有模型、注入类型化模型数据模型
声明字段、主键、关联、唯一约束及模型插件用注解定义数据模型
编写普通业务服务与 HTTP 接口Controller 与 Service
划定事务，传播异常，安排后台执行身份事务、异常与后台身份
实现和调用业务动作，监听业务事件业务模型
让 Java 与可视化编排互相调用逻辑流模型
将动作或流程暴露为 HTTP 接口WebAPI 模型
调用外部服务并复用参数、认证和接口定义RPC 模型
发送、消费消息，编写后台任务消息队列、计划任务
使用配置、字典、通知、实时通信、上传与组织服务平台支撑能力
随模块或应用补齐基础数据数据初始化

各入口的选择与调用关系见 后端开发总览。

前端开发​

在现有页面上调整 Schema，或将定制界面作为微前端接入宿主。前端开发先确认生命周期、资源路径和接口，再扩展布局与工作台。

要完成的事教程
选择页面、布局和组件的实现位置前端开发总览
接入工程、构建资源和宿主生命周期应用改造
接入独立页面或子应用微前端应用
编写 Schema、事件和动作PrismUI 开发参考
定制顶栏、侧栏与导航布局组件
组合首页、看板与可配置内容工作台与 Widget
上传和更新构建包微前端包管理

认证与权限​

开发业务入口时就要明确谁可以访问、能够操作哪些数据。已有平台账号可以先配置授权；需要企业身份登录或品牌登录页时，再增加相应接入。

要完成的事教程
规划主体、Claims、接口权限与数据范围权限与访问控制
定义数据权限参数、授权表单与查询约束数据权限参数的定义与使用
接入企业目录、统一认证服务或企业协作平台认证接入：AD、OIDC、CAS、钉钉、企业微信、飞书
定制登录交互、多种认证入口与语言切换自定义登录页

集成、自动化与实时能力​

外部调用、消息处理、任务触发和页面推送需要共同完成一个业务时，按 集成、自动化与实时能力安排各阶段的输入、状态、重试和最终结果。单个接口或任务可直接使用对应后端教程。

测试与调试​

先用 自动化测试检查业务规则、真实模型读写、回滚和权限，再从目标应用的真实入口联调。断点调试方式按代码运行位置选择：

代码运行位置调试方法
开发平台管理的测试实例平台测试实例调试
本机的标准基座容器本地基座容器调试
工程自己的 Spring Boot 进程内嵌基座调试

插件扩展​

一项实现需要被多个模型或应用复用时，可以进一步整理为组件、节点、上下文或模型插件。先查 平台扩展点总表，确定对应能力的注册与调用机制。
