# 开发平台辅助能力

模型、页面、流程或扩展通过功能验证后，需要为目标应用固定环境、实例和配套版本。AI 可以协助核对配置、整理产物及执行当前环境已有的检查，具体操作仍通过平台和项目的正式入口完成。

## 准备交付清单

交付任务写明应用、目标环境、实例、允许执行的操作，以及本次涉及的模型、前端包、后端 JAR 和组件库。让 AI 对照实际变更整理清单，确认每项产物的版本与引用；凭据继续使用环境配置。

只有配置变化的任务也需要记录应用版本。涉及新增产物时，再按下文补齐安装、实例更新和回退步骤。具体界面操作使用对应菜单指南。

## 1. 绑定数据源

平台级数据源维护外部数据库连接定义，应用级数据源把应用内的数据站点映射到平台数据源。连接信息由平台配置管理，扩展代码继续通过平台的数据访问能力使用它。

1. 在 [平台数据源](../low-code/development-platform-menus/platform-datasource) 中维护各环境的连接、凭据和 JDBC 驱动。
2. 在应用的 [数据源](../low-code/development-platform-menus/datasource) 页面配置绑定。
3. 在目标运行环境验证连接及业务读写，检查元数据、时区、事务和账号权限。

平台支持 JDBC 元数据读取以及表、字段探查。切换绑定不会自动迁移数据库数据，开发环境连接成功也不能替代目标环境验证。

## 2. 确认环境与运行实例

平台内建 `dev`、`test`、`uat`、`prod` 环境语义。实例运行环境、数据源定义和配置需要对应；profile 与实例的实际绑定以平台返回结果为准。

[运行实例](../low-code/development-platform-menus/runtime-instance) 提供创建、启动、停止、重启、删除、状态查询和基座镜像管理；暂停等操作以当前运行时后端支持的能力为准。平台也通过状态事件回传实例变化。

联调前核对应用、profile、实例状态和镜像版本。后端扩展上传、重启和断点调试见 [本地 IDE 与线上平台联调](./local-ide-and-platform-debugging)。

## 3. 固定交付版本

[版本管理](../low-code/development-platform-menus/version-management) 基于 Git/VCS 管理开发资产，提供文件状态、锁定、提交、变更记录、版本列表、创建版本和导出能力。

交付前让开发者或 AI 对照变更清单确认版本覆盖本次模型和配置变更，并记录配套的前端包、后端 JAR、组件库及平台版本。导出应用时，明确是否包含未提交内容和 Git 仓库信息。创建版本记录后，运行实例仍需按发布流程更新。

## 4. 安装、验收与回退

| 交付物 | 安装与管理入口 | 验证重点 |
| --- | --- | --- |
| 微前端、布局和应用组件库 | [微前端包管理](../guide/advance/extend-frontend/) | 资源路径、挂载入口和页面引用 |
| 后端 JAR | [后端扩展包管理](../low-code/development-platform-menus/backend-extension-package) | 自动配置、SPI、元数据与业务调用 |
| 跨应用组件库 | [平台组件库安装](./plugin-extensions/frontend/platform-component-library) | 清单、版本、应用导入和引用关系 |
| 应用模型与配置版本 | [应用发布与回滚](../operations/application-release-and-rollback) | 目标环境、模型版本与运行结果 |

按 [任务协作与交付验收](./high-low-code-collaboration) 使用约定数据与账号验收，保留上一版产物和配置。卸载前清理业务引用；回退时同步核对产物、元数据与配置，确认实例能恢复启动并完成关键业务。

## 整理执行结果

记录实际使用的版本、更新的实例、执行的检查和业务结果。AI 生成的部署步骤与已经完成的操作分别列出，尚未执行的验证保留为待办，并交接所需环境和复现数据。

## 与外部交付体系协作

需要组织级流水线、制品库、签名或基础设施治理时，可由外部 DevOps 体系编排。平台内的模型管理、实例控制和发布仍通过正式入口执行，保持应用版本与运行状态可追溯。

部署与日常维护见 [运维管理](../operations/)。
