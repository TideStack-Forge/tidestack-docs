# 文件与文档维护

上传文件和文档库需要同时维护文件内容、数据库元数据与访问权限。先确认文件由哪个应用、哪种存储后端管理，再确定挂载、容量和备份策略。

## 确认实际存储位置

| 能力 | 配置 | 需要核对 |
| --- | --- | --- |
| 文件上传 | `ouroboros.upload.fileSystem.rootPath` | 镜像基座默认 `/app/deploy/data/uploads`，以实际生效配置为准 |
| 文档库本地存储 | `ouroboros.document-management.storage.filesystem.base-path` | 启用该模块后配置的根目录及持久卷 |
| 自定义或外部存储 | 对应存储实现的配置 | 存储桶、对象键、访问凭据与生命周期规则 |

配套 Compose 把部署目录挂载为 `/app/deploy`。平台默认上传目录因此落在宿主机 `data/uploads/`，不在 `workspace/` 中；业务实例另有自己的挂载和配置，不能直接沿用平台路径。

文档库根目录如果位于 `/app/deploy` 之外，需要单独挂载。只创建容器内目录不能保证重建后文件仍然存在。

## 建立维护清单

为每个实际启用的存储记录：

- 所属应用、存储后端和容器内路径。
- 对应宿主机目录、持久卷或存储桶。
- 元数据所在数据库、目录所有者与权限范围。
- 容量阈值、保留周期和备份任务。
- 恢复时需要配套的数据时间点。

变更路径或切换存储前，先核对已有文件迁移、URL 访问和权限恢复方案。

## 日常检查

1. 检查实际存储的可用空间、增长速度和挂载状态。
2. 使用有权限账号上传一份可识别的测试文件，再下载核对内容。
3. 在文档库中检查目录、所有者、重命名和下载。
4. 使用无权限账号确认受限文档不能访问。
5. 检查临时文件清理与保留策略，按业务归属处理过期数据。

清理前确认文件没有业务引用并符合保留策略。不要只依据修改时间批量删除上传目录或文档库内容。

## 按现象检查

| 现象 | 检查顺序 |
| --- | --- |
| 上传失败 | 请求大小限制 → 目标目录权限 → 剩余容量 → 应用日志 |
| 元数据存在但文件下载失败 | 实际存储路径 → 文件是否存在 → 挂载与迁移记录 |
| 只有部分账号失败 | 文档所有者与 ACL → 当前用户身份 → 访问日志 |
| 重建容器后文件消失 | 是否保存在容器层或临时卷 → 实际持久化挂载 |
| 文件恢复后页面仍不可用 | 数据库与文件时间点 → 文件引用 → 目录权限与 URL |

## 备份与恢复验证

同一恢复点应包含数据库元数据、文件内容和访问控制。完整步骤见 [备份与恢复](./backup-monitoring-and-troubleshooting)。

恢复后验证附件上传、下载、测试文件删除，以及文档库目录、所有者与 ACL。涉及多实例时，从不同实例访问同一份文件，确认存储共享方式符合预期。

任务、消息和实时推送的维护见 [专项链路维护](./task-message-and-realtime-link-maintenance)；用户操作追查见 [业务日志与审计回溯](./business-logs-and-audit-traceability)。
