# 组织、权限、配置与通知

这四类能力分别回答：人员属于哪里、人员可以做什么、运行参数取什么值、业务事件通知谁。

## 何时使用

| 问题 | 使用能力 |
| --- | --- |
| 部门负责人、员工归属和岗位关系如何确定 | 组织架构 |
| 谁能看到菜单、调用接口或操作数据 | 用户角色权限 |
| 阈值、开关和默认值需要上线后调整 | 配置项 |
| 待办、结果和异常需要触达相关人员 | 消息通知 |

登录认证只确认用户身份；组织架构和权限决定该身份在业务中的关系与访问范围。

## 配置顺序

1. 在 [组织架构](../guide/module/organization/) 中建立公司、部门、岗位和员工。
2. 在 [用户角色权限](../guide/module/rbac/) 中创建角色、分配用户，并配置页面、接口和数据范围。
3. 在 [配置项](../guide/tutorial/configuration/) 中定义需要按环境或客户调整的参数。
4. 在 [消息通知](../guide/tutorial/notification/) 中配置渠道、模板和接收人来源。
5. 使用至少两个角色执行一次完整业务流程。

## 验收

- 审批候选人和通知接收人能从组织关系中正确解析。
- 无权限角色看不到菜单，并且直接调用接口也会被拒绝。
- 不同数据范围的角色查询到的数据不同且符合规则。
- 修改配置项后，消费该配置的功能按预期生效。
- 通知模板变量能被替换，发送失败有可查询记录。

需要接入外部身份、Claims 或字段级访问控制时，使用 [权限、主体与访问控制设计](../fusion-development/authority-subject-and-access-control-design)。
