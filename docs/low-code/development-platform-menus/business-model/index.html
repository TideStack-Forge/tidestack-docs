业务模型

业务模型用于定义业务对象及其标准能力。字段和关联描述数据结构，视图配置决定列表和表单如何呈现，接口配置和访问控制约束数据读写，行为契约进一步定义动作、事件以及事件订阅。

在业务模型页面中，可以完成从新建模型到调试验证的完整配置。通常先确定模型的基本信息、字段和关联，再配置视图与接口；工作流、高级特性、访问控制和自定义功能根据实际需要启用。

开始前​

开始配置前，确认当前账号可以编辑应用，并提前确定以下内容：

  • 模型名：模型的稳定标识，以字母开头，只能包含字母和数字。
  • 模型标题：显示在开发界面和业务页面中的名称。
  • 所属模块：用于在模块树和应用菜单中组织模型。
  • 核心字段：至少明确主键、显示字段、必填字段和唯一字段。
  • 关联对象：需要建立主表、子表或引用关系时，先确认目标业务模型已经存在。

模型名会用于模型全名及相关页面、接口的标识。创建前应尽量确定稳定的命名，避免后续重命名影响已有引用。

打开业务模型​

打开应用后，在左侧开发菜单中选择 业务模型。页面左侧是模块树，右侧是当前模块中的业务模型列表。

使用模块树​

模块树用于按业务范围组织模型。选择一个模块后，右侧列表只显示该模块中的模型；选择 全部模型 可以查看整个应用的模型。

需要新增、重命名或调整模块时，点击 管理模块树。模块树只负责组织模型，不改变模型本身的字段、视图和接口配置。

新建业务模型​

  1. 在业务模型列表右上角点击 新建。
  2. 选择模型类型和所属模块。
  3. 填写模型名和模型标题。
  4. 按需选择图标并填写模型描述。
  5. 确认表单，返回业务模型列表。

模块否模型在模块树中的位置。未选择时，模型位于模块树根级。
模型名是模型标识，以字母开头，只能包含字母和数字。

创建成功后，新模型会出现在列表中。此时模型只有基本信息，需要继续进入编辑器配置字段、视图和接口。

编辑业务模型​

点击模型行中的 编辑。平台会先锁定模型，再打开业务模型编辑器；其他用户在锁释放前只能查看，不能同时编辑。

配置字段与关联​

字段与关联决定模型的数据结构。先添加字段，再根据模型之间的实际关系配置关联。

添加业务字段​

在 字段与关联 中找到 业务字段，点击 新增，逐项填写字段信息。字段可以拖动排序，也可以使用 导入字段 一次加入已有字段定义。

建立模型关联​

当当前模型需要引用或包含另一个业务模型时，在 关联模型 中点击 新增。

配置项说明
关系名关系标识，不能与当前模型中的字段名重复。
显示名关系在页面和配置界面中的标题。
类型选择主表、子表或引用。
模型选择关系指向的业务模型。
引用键新建主表或引用关系时，指定目标模型中被引用的键；留空时使用目标模型的主键。子表关系在关系属性中配置关联键。

三类关系的用途不同：

  • 主表：外部模型是当前模型的上级对象。
  • 子表：外部模型是当前模型包含的明细集合；目标模型需要先建立指向当前模型的主表关系。
  • 引用：当前模型引用一个独立对象，但两者不构成主表与子表的组成关系。

配置行为契约​

打开 行为契约。Action 描述可以请求执行的业务动作，Event 描述已经发生的业务事实，Event Subscription 定义收到事件后由谁、如何处理。例如，“完成任务”是动作，“任务已完成”是事件，收到事件后更新统计是订阅的处理责任。

标准搜索、新建、更新等动作来自接口配置，数据变更事件来自平台的数据操作能力；需要额外的业务动作或事件时，再在本页新增定义。

查看动作、事件及其来源​

在 查看范围 中选择 当前完整草稿，点击 预览当前完整草稿。目录会汇总当前输入中的动作、事件和订阅，并标明它们来自模型动态定义、平台生成还是代码贡献。选择成员可以查看契约、实现绑定、生产来源和引用关系；修改后需要重新预览，旧结果不能代表当前草稿。

选择 目标应用已发布契约 时，需要填写目标应用 API 地址；跨应用访问还要提供目标应用访问令牌，再加载目标应用的目录。这里反映运行应用当前加载的契约，适合核对部署结果。开发环境的草稿预览只包含当前实际加载的代码贡献，不能代替目标应用核验。

平台生成的标准动作应回到 接口配置 或相应特性中维护；代码贡献应回到扩展包维护。不要在动态定义中新增同名成员覆盖它们。

定义 Action​

在 Actions 页签点击 新增自定义动作。默认使用结构化编辑，也可以点击 切换 JSON 高级编辑 直接维护动作数组。切换前先修正当前 JSON 中的错误。

配置项说明
动作名称动作在当前模型内的稳定标识，必填。不能与已有标准动作、特性动作或代码贡献重名。
标题动作的显示名称，例如“完成任务”。
业务语义说明说明动作的业务用途、输入和预期结果。
动作状态选择启用或停用。停用后不可执行。
是否只读只查询数据时选择只读；写入数据或产生外部副作用时选择允许写入。只读动作不能通过实现绕过写入约束。
输入 Schema（根为 params / data）用 JSON Schema 约束业务输入。根对象只允许 params 和 data：前者放操作参数，后者放业务载荷。
输出 Schema用 JSON Schema 声明动作返回结果。调用方应按此契约读取结果。
实现绑定选择逻辑流或高代码 Handler。契约本身不提供实现。
逻辑流名称绑定逻辑流时填写，必须引用已存在、可执行的逻辑流。
逻辑流输入映射把动作输入映射为逻辑流的工作数据。表达式通过 input.params、input.data 读取业务输入，通过 context 读取可信执行上下文。
逻辑流输出映射把逻辑流执行结果整理为动作输出，结果仍需符合输出 Schema。
Handler 名称绑定高代码 Handler 时填写，必须与扩展包中已经注册的实现名称一致。
依赖 HTTP 请求实现确实需要同步 HTTP 请求上下文时选择需要。此类动作不能由没有 HTTP 上下文的后台事件消费直接执行。
前置条件表达式执行前检查业务状态的布尔表达式，可读取业务输入及已授权的对象状态。它是受限谓词，不支持任意方法调用或副作用。
前置条件不满足时的提示前置条件为假时向调用方解释原因，例如“只有待办任务可以开始”。
允许发出的事件引用事件引用数组，每项填写 modelFullName 和 eventName。它限定实现允许发出哪些事件，声明本身不会自动产生事件。

例如，只接收任务编号的动作，可以把输入 Schema 写成：

{
  "type": "object",
  "additionalProperties": false,
  "required": ["params"],
  "properties": {
    "params": {
      "type": "object",
      "additionalProperties": false,
      "required": ["taskId"],
      "properties": {"taskId": {"type": "string"}}
    }
  }
}

对应输入是 {"params":{"taskId":"任务编号"}}。涉及对象状态判断或数据权限时，还需在 Schema 中声明业务对象引用，由服务端读取并授权；客户端传来的状态不能作为授权依据。

升级已有模型格式​

新建模型使用 2.0 格式，动作在行为契约中唯一定义，自定义功能引用动作。已有模型需要升级时，先使用本页的格式升级预览，核对关系校验、动作迁移和输入映射的变化，再应用升级。升级后重新检查自定义功能的页面入口和 API，并在目标实例验证调用结果。

添加自定义功能​

标准页面和标准接口无法覆盖某项操作时，可以增加自定义功能，为业务模型补充页面入口、自定义 API，或者把两者组合成一个完整操作。

点击 新增 后，先配置用于识别功能的基本字段：

字段是否必填说明
名字是功能的稳定标识。必须以字母开头，只能包含字母和数字，不能使用 add、create、update、delete 等保留字；创建后不能修改。
标题是功能在编辑器和默认运行入口中显示的名称，创建后仍可修改。
图标否功能的默认图标。未单独配置按钮图标时，UI 入口沿用此图标。

创建功能后，展开该功能可以继续维护基本信息：

字段是否必填说明
名字是显示创建时确定的功能标识。该字段只读。
标题是修改功能的显示名称。按钮文字留空时，也会使用此标题。
图标否修改功能的默认图标。
功能描述否说明功能的用途、适用对象或执行结果，便于后续维护。

UI 配置和 API 配置可以单独启用。只需要页面入口时启用 UI；只需要提供接口时启用自定义 API；页面入口需要直接调用当前接口时，同时启用两项。

提供页面入口​

打开 UI 配置，先配置入口的位置和行为：

字段出现条件说明
启用始终在运行页面中提供当前功能的 UI 入口。名字或标题为空时不能开启。
入口启用 UI 后选择功能入口的呈现位置：工具栏位于索引页工具栏，适合不依赖当前记录的操作；操作列位于每条记录末尾，适合直接处理当前记录；单条动作在选中一条记录后可用；批量动作在选中多条记录后可用。
打开方式启用 UI 后选择点击入口后的动作。弹窗、抽屉和新标签打开自定义页面；API 调用直接请求当前功能的 API；自定义通过 Schema 定义完整按钮行为。
对齐方式入口为工具栏时设置入口在工具栏中左对齐或右对齐。
按钮顺序启用 UI 后按数值从小到大排列同一区域的按钮。可参照操作列内置的查看、编辑、删除按钮顺序 10、20、30，以及工具栏新建按钮顺序 10，把自定义入口插入预期位置。
禁用条件打开方式不是自定义时填写判断按钮是否禁用的表达式，例如 ${status == 1}。操作列和单条动作可以引用当前记录字段，批量动作应根据所选数据编写条件。

展开 按钮样式 后，可以逐项调整入口外观：

字段说明
样式选择按钮的语义样式，包括默认、主要、次要、提示、成功、警告、危险、浅色、深色、强调和链接。样式应与操作的重要程度和风险一致。
尺寸选择极小、小、中等或大。操作列内按钮通常使用较小尺寸，工具栏入口应与相邻按钮保持一致。
按钮文字设置入口上显示的文字；留空时使用功能标题。
显示按钮文字控制是否显示按钮文字。关闭后只显示图标，因此应同时配置含义明确的按钮图标。
按钮图标设置入口使用的图标；留空时使用功能图标。
背景颜色覆盖当前样式的按钮背景色。没有明确的视觉规范时保持为空，沿用所选样式。
文字颜色覆盖当前样式的文字和图标颜色。需要同时检查与背景色的对比度。

打开方式为 自定义 时，按钮样式和禁用条件由自定义按钮 Schema 决定，上述字段不显示。

配置页面打开方式​

选择弹窗、抽屉或新标签后，通过 设计页面 创建或编辑当前功能的 UI Schema。首次设计时需要选择页面类型：

选项说明
表单创建以填写和提交数据为主的表单 Schema。
页面创建可自由组合展示、操作和数据组件的页面 Schema。

不同打开方式还会显示对应的容器字段：

字段出现条件说明
弹窗尺寸打开方式为弹窗时选择超小、小、中、大、超大或全屏，决定弹窗占用的页面空间。
抽屉尺寸打开方式为抽屉时选择超小、小、中、大或超大，决定抽屉的初始宽度。
可拖动改变大小打开方式为抽屉时允许使用者拖动抽屉边界调整宽度。内容较多或需要对照主页面时可以开启。

选择 新标签 时没有额外的容器字段，设计好的页面会在新标签中打开。

配置 API 调用反馈​

打开方式为 API 调用 时，必须先在当前功能的 API 配置 中启用自定义 API。随后可以配置调用确认、成功反馈和后续跳转：

字段出现条件说明
调用前确认打开方式为 API 调用时点击入口后先显示确认框，使用者确认后才发送请求。删除、提交、状态变更等难以撤销的操作应开启。
标题开启调用前确认后设置确认框标题；留空时使用平台默认标题。
文字开启调用前确认后设置确认提示内容，必填。操作列入口可以用 ${字段名} 引用当前记录的字段值。
成功反馈弹窗打开方式为 API 调用时API 调用成功后显示反馈弹窗。需要展示处理结果或下一步提示时开启。
弹窗标题开启成功反馈弹窗后设置反馈弹窗标题；留空时使用平台默认标题。
弹窗内容开启成功反馈弹窗后使用 Schema 编辑器定义反馈内容，必填；可以展示接口返回的数据。
成功后打开页面打开方式为 API 调用时API 调用成功后打开指定页面。
页面地址开启成功后打开页面后填写要打开的页面地址，必填。操作列入口可以用 ${字段名} 引用当前记录的字段值。

自定义按钮行为​

打开方式为 自定义 时，使用 自定义按钮 字段编写按钮 Schema。该 Schema 同时决定按钮的外观、禁用条件和点击行为，必须包含有效的按钮配置。此方式适合标准弹窗、抽屉、新标签和 API 调用均无法覆盖的交互。

提供自定义 API​

打开 API 配置，开启 启用自定义 API，设置请求方法、地址和实现方式。新建模型采用 2.0 格式，功能通过引用 Action 复用业务契约；输入、输出和前置条件在 行为契约 中统一维护。

配置项出现条件说明
启用自定义 API始终为当前功能提供接口。名字或标题为空时不能开启。
请求方法启用自定义 API 后选择 GET、POST、PUT、PATCH 或 DELETE，应与业务动作及调用方约定一致。
接口地址启用自定义 API 后必填。相对地址使用界面显示的模型路径前缀；以 / 开头时使用应用级路径。
实现方式启用自定义 API 后选择调用业务动作或调用普通接口。前者经过 Action 契约、权限和执行过程；后者由高代码 Controller 提供 REST 实现。
引用 Action调用业务动作先点击 读取完整草稿的动作，再选择目标动作。多个功能可以引用同一动作，关闭当前 API 不会停用目标动作。
HTTP 输入映射调用业务动作用 JSON 对象显式映射请求来源到 params、data，如 {"params.record.id":"${ request.pathVariables['id'] }","data":"${ request.body }"}。无输入时填 {}。

动作列表反映当前完整草稿；修改模型后要重新读取。目录未覆盖目标环境的代码贡献时，已有动作引用会保留，不会因本次未查到而自动清空。需要修改动作本身时，点击 打开业务行为契约 回到定义来源。

快捷创建脚本动作​

需要用脚本实现新功能时，在 调用业务动作 下点击 新建脚本动作。先保存 2.0 格式模型，再按以下步骤操作：

  1. 填写新动作名称，选择 JavaScript 或 Groovy。
  2. 编写脚本，通过 $input.params、$input.data 读取输入，通过 $input.context 读取执行上下文。同步 HTTP 请求位于 $input.context.request，后台调用不能假定它存在。
  3. 在 执行效果 中选择只读或允许写入。
  4. 点击 预览脚本动作资源，逐项检查模型和逻辑流的保存前后差异。
  5. 确认无误后点击 确认创建并提交完整资源。

此操作会保存当前完整模型草稿，创建唯一的 Action 和正式逻辑流，并更新当前功能引用；原动作保留。修改脚本或草稿后，需要重新预览。点击 取消创建 不修改文件。

未填写 HTTP 输入映射时，快捷创建会提供从 request.params、request.body 到 params、data 的默认映射；已有映射保留。创建后应回到行为契约，进一步收紧输入类型、必填字段和业务前置条件。

已有旧格式模型可能仍显示 生成接口实现、绑定同名业务 Action、自定义逻辑流 和脚本配置。维护这类模型时，先通过行为目录核对实际来源，升级格式前检查迁移预览，不要把旧位置的契约再复制成第二份动作定义。

保存、提交和放弃变更​

编辑器提供 保存 和 保存并提交，两者用途不同：

操作结果适用场景
保存保存当前修改并执行后端校验，修改仍处于未提交状态，模型继续保持编辑锁。分阶段配置、预览页面或暂时保留草稿。
保存并提交先保存并校验，再填写修改说明，把当前修改写入变更记录。一组配置已经完成并可以交给其他人继续使用。
取消关闭编辑页；存在未保存修改时会提示确认。不保留本次尚未保存的页面输入。
放弃变更并解锁回到上一次提交的版本并释放编辑锁，操作不可撤销。整组未提交修改都不再需要。

点击 保存并提交 后，为本次修改填写能够说明内容的提交信息，例如“补充编辑表单字段和查询权限”。

如果保存后提示后端校验错误，修改已经保存，但模型仍有需要处理的问题。根据页面警告或列表中的错误详情修正配置，再重新保存并提交。

维护已有模型​

重命名、移动和删除​

在模型未被编辑锁定时，打开行末的更多操作，可以重命名、移动或删除模型。

  • 重命名 会改变模型标识。执行前检查页面、接口、逻辑和其他模型中的引用。
  • 移动模型 只调整模型在模块树中的位置。
  • 删除模型 前先确认它没有被其他模型、页面、流程或接口引用，并确认不再需要对应数据。

查看模型详情和投射模型​

点击模型名称或 查看详情，可以查看基本信息、完整模型定义和投射模型。编辑器中没有未保存内容时，也可以点击 查看投射模型。

投射模型用于核对业务模型对应的数据模型、页面模型、接口模型、菜单模型和权限模型等结果。这里适合检查结果，不用于替代业务模型编辑器中的源配置。

查看变更记录​

选择 查看变更记录，可以查看每次提交的时间、提交信息和作者。

提交信息应写明本次修改的对象和目的，避免使用“修改”“调整”等无法帮助后续排查的描述。

在调试实例中验证​

完成配置后，按以下顺序检查模型是否可以使用：

  1. 在基本信息中打开 启用模型。
  2. 确认索引页、新建表单、编辑表单和详情页已经按需要打开。
  3. 点击 保存并提交，并填写修改说明。
  4. 使用页面预览分别检查四类视图。
  5. 在应用顶部的调试工具栏中启动调试实例；实例已经运行时，点击 热刷新应用。
  6. 打开调试应用，检查模型菜单和索引页。
  7. 新建一条测试数据，再依次检查查询、查看、编辑和删除。
  8. 使用目标角色登录，检查字段权限、数据范围和操作权限。

验证不应停留在“页面能打开”。至少需要确认一条数据能够完成新建、查询、查看和编辑；启用了删除、工作流、自定义功能或导入导出时，还要分别验证对应路径。

常见问题​

为什么不能编辑业务模型？​

模型可能被其他用户锁定。查看列表中的锁定状态和锁定人，等待对方提交或解锁。

为什么保存按钮不可用？​

当前页面没有检测到修改。确认配置值已经发生变化后再保存。

为什么保存后仍有错误标识？​

打开错误详情，根据错误范围修正字段、关系、视图或接口配置，再重新保存。

为什么预览页面按钮不可用？​

当前模型存在尚未保存的修改。先保存模型，再打开预览页面。

为什么新建或编辑表单缺少字段？​

检查对应视图的 表单字段，确认字段已经加入，并检查字段访问控制。

为什么索引页没有显示预期列？​

检查索引页的 显示列，并确认目标角色拥有相应字段的查询权限。

为什么服务端导出找不到新增字段？​

先保存业务模型，再回到服务端数据导出配置中点击 刷新字段。

为什么调试应用中没有模型菜单？​

确认模型已启用、不是附属模型、视图已启用，并且修改已经保存并提交。完成后，在顶部调试工具栏中热刷新应用。

为什么页面可以打开，却不能新建或更新数据？​

检查对应的标准接口是否启用、访问控制是否开启，以及目标角色是否获得相应权限。

为什么修改没有出现在调试应用中？​

确认修改已经提交，并对运行中的调试实例执行热刷新。
