# 业务模型

业务模型用于定义业务对象及其标准能力。字段和关联描述数据结构，视图配置决定列表和表单如何呈现，接口配置和访问控制约束数据读写，行为契约进一步定义动作、事件以及事件订阅。

在业务模型页面中，可以完成从新建模型到调试验证的完整配置。通常先确定模型的基本信息、字段和关联，再配置视图与接口；工作流、高级特性、访问控制和自定义功能根据实际需要启用。

## 开始前

开始配置前，确认当前账号可以编辑应用，并提前确定以下内容：

- 模型名：模型的稳定标识，以字母开头，只能包含字母和数字。
- 模型标题：显示在开发界面和业务页面中的名称。
- 所属模块：用于在模块树和应用菜单中组织模型。
- 核心字段：至少明确主键、显示字段、必填字段和唯一字段。
- 关联对象：需要建立主表、子表或引用关系时，先确认目标业务模型已经存在。

模型名会用于模型全名及相关页面、接口的标识。创建前应尽量确定稳定的命名，避免后续重命名影响已有引用。

## 打开业务模型

打开应用后，在左侧开发菜单中选择 **业务模型**。页面左侧是模块树，右侧是当前模块中的业务模型列表。

![业务模型页面](.assets/business-model/business-model-list.png)

### 使用模块树

模块树用于按业务范围组织模型。选择一个模块后，右侧列表只显示该模块中的模型；选择 **全部模型** 可以查看整个应用的模型。

需要新增、重命名或调整模块时，点击 **管理模块树**。模块树只负责组织模型，不改变模型本身的字段、视图和接口配置。

### 查看模型列表

模型列表提供以下信息和操作：

| 区域 | 用途 |
| --- | --- |
| 关键字与过滤 | 按模型名或模型标题查找模型。 |
| 模型 | 查看模型标题、模型名、启用状态、锁定状态和校验状态；点击模型标题可以打开模型详情。 |
| 顺序 | 查看模型在同级模块中的排列顺序。 |
| 业务字段 | 查看模型当前包含的字段数量。 |
| 文件大小、修改时间 | 判断模型规模和最近一次修改时间。 |
| 编辑 | 锁定模型并打开编辑器；模型被其他用户锁定时不能编辑。 |
| 放弃变更并解锁 | 丢弃尚未提交的修改，并释放当前用户持有的编辑锁。 |
| 更多操作 | 重命名、移动模型、立即编辑、查看变更记录或删除模型。 |

列表中的后端校验错误需要先处理，再继续提交或验证模型。点击错误标识可以查看具体错误和对应范围。

## 新建业务模型

1. 在业务模型列表右上角点击 **新建**。
2. 选择模型类型和所属模块。
3. 填写模型名和模型标题。
4. 按需选择图标并填写模型描述。
5. 确认表单，返回业务模型列表。

![新建业务模型](.assets/business-model/create-business-model.png)

| 配置项 | 是否必填 | 说明 |
| --- | --- | --- |
| 模型类型 | 是 | 选择业务模型类型；当前标准业务建模使用 **默认**。 |
| 模块 | 否 | 模型在模块树中的位置。未选择时，模型位于模块树根级。 |
| 模型名 | 是 | 模型标识，以字母开头，只能包含字母和数字。 |
| 模型标题 | 是 | 开发界面和业务页面中显示的名称。 |
| 图标 | 否 | 模型在菜单或相关入口中使用的图标。 |
| 模型描述 | 否 | 说明模型的用途和边界。 |

创建成功后，新模型会出现在列表中。此时模型只有基本信息，需要继续进入编辑器配置字段、视图和接口。

## 编辑业务模型

点击模型行中的 **编辑**。平台会先锁定模型，再打开业务模型编辑器；其他用户在锁释放前只能查看，不能同时编辑。

![业务模型编辑器](.assets/business-model/editor-overview.png)

编辑器包含基本信息以及以下配置区：

| 配置区 | 主要用途 | 通常何时配置 |
| --- | --- | --- |
| 字段与关联 | 定义字段、字段属性以及模型之间的关系。 | 每个模型都需要。 |
| 视图配置 | 配置索引页、新建表单、编辑表单和详情页。 | 需要标准业务页面时。 |
| 接口配置 | 配置搜索、获取单条、新建、更新和删除接口。 | 需要标准数据操作时。 |
| 行为契约 | 查看动作和事件目录，定义自定义动作、事件及消费方订阅。 | 需要明确业务动作或事件协作时。 |
| 工作流配置 | 将模型动作与审批流程连接。 | 业务操作需要审批时。 |
| 高级特性 | 配置软删除、审计字段、批量删除、导入和服务端导出等能力。 | 有相应数据管理要求时。 |
| 访问控制 | 打开查询、新建、更新和删除的控制维度。 | 需要按角色、字段或组织范围限制数据操作时。 |
| 自定义功能 | 增加标准页面和接口之外的 UI 入口或 API。 | 标准能力无法覆盖时。 |

建议先完成字段与关联，再配置视图和接口。接口配置和访问控制在模型尚无字段或关联时不可用。

### 配置基本信息

基本信息默认折叠，先点击右侧 **展开** 再修改标题、图标、描述等信息。启用开关可以直接控制模型是否参与运行。

| 配置项 | 说明 |
| --- | --- |
| 模型 | 只读显示模型全名，用于确认当前正在编辑的模型。 |
| 启用模型 | 控制模型是否参与应用运行。新建模型默认未启用；准备验证标准页面和接口前需要启用。 |
| 模型标题 | 模型在开发界面和业务页面中的显示名称，必填。 |
| 图标 | 模型在菜单和相关入口中显示的图标。 |
| 附属模型 | 将模型标记为其他模型的组成部分，不为它提供独立菜单入口。 |
| 排序 | 控制模型在同级模块中的顺序，必填；数值越小越靠前。 |
| 模型描述 | 记录模型的用途和边界。 |

点击 **高级设置** 可以配置数据存储位置：

| 配置项 | 说明 |
| --- | --- |
| 数据源 | 指定模型使用的数据源名称。留空时使用应用的默认数据配置。 |
| 原始表名 | 模型对应的数据库表名。未选择数据源时可以直接填写；选择数据源后，可以从该数据源已有表中选择，也可以新增表名。 |

只有确实要接入指定数据源或已有表时才使用 **高级设置**。普通模型沿用应用默认数据配置即可。

### 配置字段与关联

字段与关联决定模型的数据结构。先添加字段，再根据模型之间的实际关系配置关联。

#### 添加业务字段

在 **字段与关联** 中找到 **业务字段**，点击 **新增**，逐项填写字段信息。字段可以拖动排序，也可以使用 **导入字段** 一次加入已有字段定义。

![业务字段](.assets/business-model/fields-and-relations.png)

| 配置项 | 说明 |
| --- | --- |
| 字段名 | 字段的稳定标识，不能与当前模型中的其他字段名或关系名重复。字段设为主键后不能在属性弹窗中修改名称。 |
| 显示名 | 字段在表单、表格和详情页中的默认标题。 |
| 类型 | 决定字段存储方式、默认输入组件和显示组件。 |
| 主键 | 将字段设为模型主键。一个模型只能有一个主键；主键同时为必填和唯一。 |
| 必填 | 新建数据时必须提供该字段。主键或唯一字段会自动设为必填，不能单独关闭。 |
| 值唯一 | 字段值不能重复；启用后字段同时为必填。 |

一个字段应只表达一个稳定属性。不要为了减少字段数量，把多个含义拼进同一文本字段；这会使过滤、校验、接口和权限配置变得困难。

#### 批量导入字段

已有 Excel 表头或字段清单时，点击 **导入字段**，通过两步向导一次生成多个字段。

第一步 **选择文件** 包含以下字段：

| 配置项 | 说明 |
| --- | --- |
| 模式 | 选择 **从表头生成字段** 或 **从字段表导入**。前者把第一个工作表的第一行作为字段标题；后者把第一个工作表的每一行作为一个字段，表头必须包含“字段名”“显示名”“类型”。两种模式都会忽略名为 `id` 的输入列。 |
| 文件 | 上传 `.xls` 或 `.xlsx` 文件，必填。平台只读取第一个工作表。 |

点击 **下一步** 后，在 **检查字段** 中逐项确认导入结果：

| 配置项 | 说明 |
| --- | --- |
| 字段名 | 检查或修改生成的字段标识。 |
| 显示名 | 检查或修改字段在页面中的默认标题。 |
| 类型 | 为每个字段选择字段类型，必填。平台无法可靠推断类型时，需要在这里修正。 |
| 主键 | 标识主键字段。向导会自动加入 `id` 主键，该项不能取消，也不能删除。 |

确认导入后，字段会加入当前模型，但仍需保存模型。逐项检查字段名、类型、必填和唯一约束；导入向导不会替代字段属性配置。

#### 设置字段属性

点击字段行末的设置按钮打开 **字段属性**。

![字段属性](.assets/business-model/field-properties.png)

| 配置项 | 说明 |
| --- | --- |
| 字段名 | 字段标识。主键字段的名称不可修改。 |
| 显示名 | 字段在页面和配置界面中的默认标题。 |
| 原始字段名 | 字段名与数据库字段名不一致时填写；留空时由平台根据字段名生成。 |
| 描述 | 说明字段的业务含义、单位、取值口径和使用限制。这里是说明文字，不执行表达式。 |
| 字段类型 | 设置字段的数据类型，并决定后续出现的类型专属配置。 |
| 作为显示字段 | 其他模型引用当前模型时，用该字段代表一条记录。主键字段不显示此选项。 |
| 主键 | 将当前字段设为模型主键。一个模型只能有一个主键。 |
| 必填 | 要求新建数据时提供该字段。主键或唯一字段会自动启用，不能单独关闭。 |
| 值唯一 | 要求当前字段的值在模型中不重复。主键字段自动唯一。 |
| 默认值 | 新建数据时使用的默认值表达式。主键字段不显示此项；字符串常量需要使用单引号。 |
| 输入组件 | 覆盖该字段在新建、编辑表单中的默认输入组件。 |
| 显示组件 | 覆盖该字段在索引页、详情页中的默认显示组件。 |
| 展开更多设置 | 打开当前字段类型的专属配置。各内置类型的字段见下表。 |

默认值表达式的语法和可用上下文见 [表达式](/docs/guide/tutorial/expression/)。字段类型及其组件配置见 [字段定义](/docs/concepts/field-define/)。

#### 建立模型关联

当当前模型需要引用或包含另一个业务模型时，在 **关联模型** 中点击 **新增**。

![关联模型](.assets/business-model/fields-and-relations.png)

| 配置项 | 说明 |
| --- | --- |
| 关系名 | 关系标识，不能与当前模型中的字段名重复。 |
| 显示名 | 关系在页面和配置界面中的标题。 |
| 类型 | 选择主表、子表或引用。 |
| 模型 | 选择关系指向的业务模型。 |
| 引用键 | 新建主表或引用关系时，指定目标模型中被引用的键；留空时使用目标模型的主键。子表关系在关系属性中配置关联键。 |

三类关系的用途不同：

- **主表**：外部模型是当前模型的上级对象。
- **子表**：外部模型是当前模型包含的明细集合；目标模型需要先建立指向当前模型的主表关系。
- **引用**：当前模型引用一个独立对象，但两者不构成主表与子表的组成关系。

![新增关联模型](.assets/business-model/add-relation.png)

新增关系后，点击关系行末的设置按钮打开 **关联属性**。

| 配置项 | 何时出现 | 说明 |
| --- | --- | --- |
| 关系名 | 始终 | 关系的稳定标识，不能与当前模型中的字段名重复。 |
| 显示名 | 始终 | 关系在页面和配置界面中的标题。 |
| 原始字段名 | 主表、引用 | 外键对应的数据库字段名；留空时由平台根据关系名生成。 |
| 描述 | 始终 | 记录关系的业务含义和使用限制。 |
| 类型 | 始终 | 选择主表、子表或引用。 |
| 关联模型 | 始终 | 选择关系指向的业务模型。 |
| 关联键 | 子表 | 选择目标模型中指向当前模型的主表或引用关系。 |
| 引用键 | 主表、引用 | 指定目标模型中被引用的字段；留空时使用目标模型主键。 |
| 同步提交 | 子表 | 决定子表数据是否随当前模型表单一起提交。 |
| 必填 | 主表、引用 | 要求表单提交时必须选择关联记录。 |
| 输入方式 | 主表、引用 | 选择 **拾取器** 或 **下拉框** 作为表单输入方式。 |
| 显示方式 | 主表、引用 | 选择在详情页中按 **详情（字段集）** 或 **表单字段** 显示关联数据。 |

**同步提交** 会把子表数据和当前模型放在同一次表单提交中处理。只有确实需要在主表表单内同时维护明细时才启用；独立维护的子表不需要打开该选项。

#### 使用 UI Schema 自定义页面

标准配置无法满足布局或交互要求时，先保存模型，再点击对应页面的 **预览页面**。在预览窗口中点击 **克隆当前 UI Schema**，平台会基于当前标准页面创建 UI Schema，并询问是否打开编辑页面。

自定义 UI Schema 会增加独立维护内容。标准页面能够满足需求时，继续在业务模型中配置字段、布局和组件即可。

### 配置标准接口

**接口配置** 包含搜索、获取单条、新建、更新和删除五类标准接口。每类接口都可以独立启用。

![接口配置](.assets/business-model/search-api.png)

默认情况下保留 **自动逻辑**，平台会按照模型字段、关联和访问控制生成标准数据操作。关闭自动逻辑后，接口改为执行完整的自定义脚本。

| 排序字段 | 启用自动逻辑 | 选择默认排序字段。内置字段仅在启用基本审计字段后提供创建时间和更新时间。 |

### 配置行为契约

打开 **行为契约**。Action 描述可以请求执行的业务动作，Event 描述已经发生的业务事实，Event Subscription 定义收到事件后由谁、如何处理。例如，“完成任务”是动作，“任务已完成”是事件，收到事件后更新统计是订阅的处理责任。

标准搜索、新建、更新等动作来自接口配置，数据变更事件来自平台的数据操作能力；需要额外的业务动作或事件时，再在本页新增定义。

![业务行为目录](.assets/business-model/behavior-catalog.png)

#### 查看动作、事件及其来源

在 **查看范围** 中选择 **当前完整草稿**，点击 **预览当前完整草稿**。目录会汇总当前输入中的动作、事件和订阅，并标明它们来自模型动态定义、平台生成还是代码贡献。选择成员可以查看契约、实现绑定、生产来源和引用关系；修改后需要重新预览，旧结果不能代表当前草稿。

选择 **目标应用已发布契约** 时，需要填写目标应用 API 地址；跨应用访问还要提供目标应用访问令牌，再加载目标应用的目录。这里反映运行应用当前加载的契约，适合核对部署结果。开发环境的草稿预览只包含当前实际加载的代码贡献，不能代替目标应用核验。

平台生成的标准动作应回到 **接口配置** 或相应特性中维护；代码贡献应回到扩展包维护。不要在动态定义中新增同名成员覆盖它们。

#### 定义 Action

在 **Actions** 页签点击 **新增自定义动作**。默认使用结构化编辑，也可以点击 **切换 JSON 高级编辑** 直接维护动作数组。切换前先修正当前 JSON 中的错误。

![自定义动作配置](.assets/business-model/behavior-action.png)

| 配置项 | 说明 |
| --- | --- |
| 动作名称 | 动作在当前模型内的稳定标识，必填。不能与已有标准动作、特性动作或代码贡献重名。 |
| 标题 | 动作的显示名称，例如“完成任务”。 |
| 业务语义说明 | 说明动作的业务用途、输入和预期结果。 |
| 动作状态 | 选择启用或停用。停用后不可执行。 |
| 是否只读 | 只查询数据时选择只读；写入数据或产生外部副作用时选择允许写入。只读动作不能通过实现绕过写入约束。 |
| 输入 Schema（根为 params / data） | 用 JSON Schema 约束业务输入。根对象只允许 `params` 和 `data`：前者放操作参数，后者放业务载荷。 |
| 输出 Schema | 用 JSON Schema 声明动作返回结果。调用方应按此契约读取结果。 |
| 实现绑定 | 选择逻辑流或高代码 Handler。契约本身不提供实现。 |
| 逻辑流名称 | 绑定逻辑流时填写，必须引用已存在、可执行的逻辑流。 |
| 逻辑流输入映射 | 把动作输入映射为逻辑流的工作数据。表达式通过 `input.params`、`input.data` 读取业务输入，通过 `context` 读取可信执行上下文。 |
| 逻辑流输出映射 | 把逻辑流执行结果整理为动作输出，结果仍需符合输出 Schema。 |
| Handler 名称 | 绑定高代码 Handler 时填写，必须与扩展包中已经注册的实现名称一致。 |
| 依赖 HTTP 请求 | 实现确实需要同步 HTTP 请求上下文时选择需要。此类动作不能由没有 HTTP 上下文的后台事件消费直接执行。 |
| 前置条件表达式 | 执行前检查业务状态的布尔表达式，可读取业务输入及已授权的对象状态。它是受限谓词，不支持任意方法调用或副作用。 |
| 前置条件不满足时的提示 | 前置条件为假时向调用方解释原因，例如“只有待办任务可以开始”。 |
| 允许发出的事件引用 | 事件引用数组，每项填写 `modelFullName` 和 `eventName`。它限定实现允许发出哪些事件，声明本身不会自动产生事件。 |

例如，只接收任务编号的动作，可以把输入 Schema 写成：

```json
{
  "type": "object",
  "additionalProperties": false,
  "required": ["params"],
  "properties": {
    "params": {
      "type": "object",
      "additionalProperties": false,
      "required": ["taskId"],
      "properties": {"taskId": {"type": "string"}}
    }
  }
}
```

对应输入是 `{"params":{"taskId":"任务编号"}}`。涉及对象状态判断或数据权限时，还需在 Schema 中声明业务对象引用，由服务端读取并授权；客户端传来的状态不能作为授权依据。

#### 定义 Event

在 **Events** 页签新增事件。事件名称表达已经发生的事实；发生条件应说明事实何时成立。

![事件配置](.assets/business-model/behavior-event.png)

| 配置项 | 说明 |
| --- | --- |
| 事件名称 | 当前模型内的事件标识，必填。 |
| 标题 | 事件显示名称，例如“任务已完成”。 |
| 业务语义说明 | 说明事件含义及订阅方可以依赖的事实。 |
| 发生条件（语义说明） | 说明何时产生该事件，是解释文字，不会作为触发表达式执行。 |
| 事件主体 | 选择模型或对象实例。实例事件需要在产生时提供对象身份。 |
| 事件载荷 Schema | 声明事件携带的 JSON 对象结构，明确字段、类型和必填项。 |
| 允许的生产者种类 | 限定允许产生此事件的生产者类别。由 Action 产生的事件使用 `action`，并在对应动作的事件引用中声明。 |
| 完整模型读取要求 | 开启后，消费者必须具备完整、无过滤的模型读取权；不能用受限的行或字段权限读取包含完整模型信息的历史事实。 |

标准数据操作会提供 `recordsCreated`、`recordsUpdated`、`recordsDeleted` 事件，载荷包含操作类型、对象 ID 集合和受影响数量。不要手工定义同名事件，也不必在标准新增、更新、删除脚本中重复发出它们。

自定义事件需要在逻辑流中通过正式的业务事件节点发出，或由后端扩展调用事件端口。仅新增事件定义或订阅，不会让事件自动发生。

![事件订阅配置](.assets/business-model/behavior-subscription.png)

| 配置项 | 说明 |
| --- | --- |
| 订阅名称 | 当前消费方模型内的订阅标识，必填。 |
| 订阅状态 | 缺省启用。停用后不再为此订阅新增投递；恢复启用不会补发停用期间的事件。 |
| 事件所属模型 | 源事件的业务模型全名。 |
| 事件名称 | 源模型中的事件标识。 |
| 真实消费身份引用 | 已存在且启用的用户身份。该身份需要源事件读取权、目标动作权限及所需数据读取权限。 |
| 事件过滤表达式／事件过滤规则 | 只消费满足条件的事实。过滤在入队时执行，修改过滤器不会删除已经入队的交付责任。 |
| 目标 Action 所属模型 | 采用 Action 处理时，填写目标动作所属模型。 |
| 目标 Action 名称 | 要执行的动作标识。 |
| Action 输入映射 | 将事件载荷映射到目标动作的 `params`、`data`，例如用 `${event.payload.taskId}` 读取载荷。 |

| Listener 字面配置 | 原样交给监听器的 JSON 配置，不作为表达式求值。 |
| Listener 动态输入映射 | 用表达式从事件和交付上下文计算监听器需要的输入。异步处理不继承源 HTTP 请求。 |

事件处理可能重试，消费逻辑应使用事件或交付标识保证幂等。停用期间已经存在的交付责任会阻塞；重新启用并修复原因后，需要有权限的用户显式重驱。

#### 检查与调用已部署的动作

在 **运行与诊断** 中点击 **检查或调用已发布 Action**。先保存并校验模型，再刷新目标运行实例；本窗口调用目标应用实际加载的契约。

#### 升级已有模型格式

新建模型使用 `2.0` 格式，动作在行为契约中唯一定义，自定义功能引用动作。已有模型需要升级时，先使用本页的格式升级预览，核对关系校验、动作迁移和输入映射的变化，再应用升级。升级后重新检查自定义功能的页面入口和 API，并在目标实例验证调用结果。

### 添加自定义功能

标准页面和标准接口无法覆盖某项操作时，可以增加自定义功能，为业务模型补充页面入口、自定义 API，或者把两者组合成一个完整操作。

![新增自定义功能](.assets/business-model/add-custom-function.png)

点击 **新增** 后，先配置用于识别功能的基本字段：

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| 名字 | 是 | 功能的稳定标识。必须以字母开头，只能包含字母和数字，不能使用 `add`、`create`、`update`、`delete` 等保留字；创建后不能修改。 |
| 标题 | 是 | 功能在编辑器和默认运行入口中显示的名称，创建后仍可修改。 |
| 图标 | 否 | 功能的默认图标。未单独配置按钮图标时，UI 入口沿用此图标。 |

创建功能后，展开该功能可以继续维护基本信息：

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| 名字 | 是 | 显示创建时确定的功能标识。该字段只读。 |
| 标题 | 是 | 修改功能的显示名称。按钮文字留空时，也会使用此标题。 |
| 图标 | 否 | 修改功能的默认图标。 |
| 功能描述 | 否 | 说明功能的用途、适用对象或执行结果，便于后续维护。 |

UI 配置和 API 配置可以单独启用。只需要页面入口时启用 UI；只需要提供接口时启用自定义 API；页面入口需要直接调用当前接口时，同时启用两项。

#### 提供页面入口

打开 **UI 配置**，先配置入口的位置和行为：

| 字段 | 出现条件 | 说明 |
| --- | --- | --- |
| 启用 | 始终 | 在运行页面中提供当前功能的 UI 入口。名字或标题为空时不能开启。 |
| 入口 | 启用 UI 后 | 选择功能入口的呈现位置：**工具栏**位于索引页工具栏，适合不依赖当前记录的操作；**操作列**位于每条记录末尾，适合直接处理当前记录；**单条动作**在选中一条记录后可用；**批量动作**在选中多条记录后可用。 |
| 打开方式 | 启用 UI 后 | 选择点击入口后的动作。**弹窗**、**抽屉**和**新标签**打开自定义页面；**API 调用**直接请求当前功能的 API；**自定义**通过 Schema 定义完整按钮行为。 |
| 对齐方式 | 入口为工具栏时 | 设置入口在工具栏中左对齐或右对齐。 |
| 按钮顺序 | 启用 UI 后 | 按数值从小到大排列同一区域的按钮。可参照操作列内置的查看、编辑、删除按钮顺序 `10`、`20`、`30`，以及工具栏新建按钮顺序 `10`，把自定义入口插入预期位置。 |
| 禁用条件 | 打开方式不是自定义时 | 填写判断按钮是否禁用的表达式，例如 `${status == 1}`。操作列和单条动作可以引用当前记录字段，批量动作应根据所选数据编写条件。 |

![自定义功能的 UI 配置](.assets/business-model/custom-ui.png)

展开 **按钮样式** 后，可以逐项调整入口外观：

| 字段 | 说明 |
| --- | --- |
| 样式 | 选择按钮的语义样式，包括默认、主要、次要、提示、成功、警告、危险、浅色、深色、强调和链接。样式应与操作的重要程度和风险一致。 |
| 尺寸 | 选择极小、小、中等或大。操作列内按钮通常使用较小尺寸，工具栏入口应与相邻按钮保持一致。 |
| 按钮文字 | 设置入口上显示的文字；留空时使用功能标题。 |
| 显示按钮文字 | 控制是否显示按钮文字。关闭后只显示图标，因此应同时配置含义明确的按钮图标。 |
| 按钮图标 | 设置入口使用的图标；留空时使用功能图标。 |
| 背景颜色 | 覆盖当前样式的按钮背景色。没有明确的视觉规范时保持为空，沿用所选样式。 |
| 文字颜色 | 覆盖当前样式的文字和图标颜色。需要同时检查与背景色的对比度。 |

打开方式为 **自定义** 时，按钮样式和禁用条件由自定义按钮 Schema 决定，上述字段不显示。

选择弹窗、抽屉或新标签后，通过 **设计页面** 创建或编辑当前功能的 UI Schema。首次设计时需要选择页面类型：

| 选项 | 说明 |
| --- | --- |
| 表单 | 创建以填写和提交数据为主的表单 Schema。 |
| 页面 | 创建可自由组合展示、操作和数据组件的页面 Schema。 |

不同打开方式还会显示对应的容器字段：

| 字段 | 出现条件 | 说明 |
| --- | --- | --- |
| 弹窗尺寸 | 打开方式为弹窗时 | 选择超小、小、中、大、超大或全屏，决定弹窗占用的页面空间。 |
| 抽屉尺寸 | 打开方式为抽屉时 | 选择超小、小、中、大或超大，决定抽屉的初始宽度。 |
| 可拖动改变大小 | 打开方式为抽屉时 | 允许使用者拖动抽屉边界调整宽度。内容较多或需要对照主页面时可以开启。 |

#### 配置 API 调用反馈

打开方式为 **API 调用** 时，必须先在当前功能的 **API 配置** 中启用自定义 API。随后可以配置调用确认、成功反馈和后续跳转：

| 字段 | 出现条件 | 说明 |
| --- | --- | --- |
| 调用前确认 | 打开方式为 API 调用时 | 点击入口后先显示确认框，使用者确认后才发送请求。删除、提交、状态变更等难以撤销的操作应开启。 |
| 标题 | 开启调用前确认后 | 设置确认框标题；留空时使用平台默认标题。 |
| 文字 | 开启调用前确认后 | 设置确认提示内容，必填。操作列入口可以用 `${字段名}` 引用当前记录的字段值。 |
| 成功反馈弹窗 | 打开方式为 API 调用时 | API 调用成功后显示反馈弹窗。需要展示处理结果或下一步提示时开启。 |
| 弹窗标题 | 开启成功反馈弹窗后 | 设置反馈弹窗标题；留空时使用平台默认标题。 |
| 弹窗内容 | 开启成功反馈弹窗后 | 使用 Schema 编辑器定义反馈内容，必填；可以展示接口返回的数据。 |
| 成功后打开页面 | 打开方式为 API 调用时 | API 调用成功后打开指定页面。 |
| 页面地址 | 开启成功后打开页面后 | 填写要打开的页面地址，必填。操作列入口可以用 `${字段名}` 引用当前记录的字段值。 |

#### 自定义按钮行为

打开方式为 **自定义** 时，使用 **自定义按钮** 字段编写按钮 Schema。该 Schema 同时决定按钮的外观、禁用条件和点击行为，必须包含有效的按钮配置。此方式适合标准弹窗、抽屉、新标签和 API 调用均无法覆盖的交互。

#### 提供自定义 API

打开 **API 配置**，开启 **启用自定义 API**，设置请求方法、地址和实现方式。新建模型采用 `2.0` 格式，功能通过引用 Action 复用业务契约；输入、输出和前置条件在 **行为契约** 中统一维护。

![自定义功能的 API 配置](.assets/business-model/custom-api.png)

| 配置项 | 出现条件 | 说明 |
| --- | --- | --- |
| 启用自定义 API | 始终 | 为当前功能提供接口。名字或标题为空时不能开启。 |
| 请求方法 | 启用自定义 API 后 | 选择 GET、POST、PUT、PATCH 或 DELETE，应与业务动作及调用方约定一致。 |
| 接口地址 | 启用自定义 API 后 | 必填。相对地址使用界面显示的模型路径前缀；以 `/` 开头时使用应用级路径。 |
| 实现方式 | 启用自定义 API 后 | 选择调用业务动作或调用普通接口。前者经过 Action 契约、权限和执行过程；后者由高代码 Controller 提供 REST 实现。 |
| 引用 Action | 调用业务动作 | 先点击 **读取完整草稿的动作**，再选择目标动作。多个功能可以引用同一动作，关闭当前 API 不会停用目标动作。 |
| HTTP 输入映射 | 调用业务动作 | 用 JSON 对象显式映射请求来源到 `params`、`data`，如 `{"params.record.id":"${ request.pathVariables['id'] }","data":"${ request.body }"}`。无输入时填 `{}`。 |

动作列表反映当前完整草稿；修改模型后要重新读取。目录未覆盖目标环境的代码贡献时，已有动作引用会保留，不会因本次未查到而自动清空。需要修改动作本身时，点击 **打开业务行为契约** 回到定义来源。

#### 快捷创建脚本动作

需要用脚本实现新功能时，在 **调用业务动作** 下点击 **新建脚本动作**。先保存 `2.0` 格式模型，再按以下步骤操作：

1. 填写新动作名称，选择 JavaScript 或 Groovy。
2. 编写脚本，通过 `$input.params`、`$input.data` 读取输入，通过 `$input.context` 读取执行上下文。同步 HTTP 请求位于 `$input.context.request`，后台调用不能假定它存在。
3. 在 **执行效果** 中选择只读或允许写入。
4. 点击 **预览脚本动作资源**，逐项检查模型和逻辑流的保存前后差异。
5. 确认无误后点击 **确认创建并提交完整资源**。

![创建脚本动作](.assets/business-model/custom-action-reference.png)

此操作会保存当前完整模型草稿，创建唯一的 Action 和正式逻辑流，并更新当前功能引用；原动作保留。修改脚本或草稿后，需要重新预览。点击 **取消创建** 不修改文件。

未填写 HTTP 输入映射时，快捷创建会提供从 `request.params`、`request.body` 到 `params`、`data` 的默认映射；已有映射保留。创建后应回到行为契约，进一步收紧输入类型、必填字段和业务前置条件。

已有旧格式模型可能仍显示 **生成接口实现**、**绑定同名业务 Action**、**自定义逻辑流** 和脚本配置。维护这类模型时，先通过行为目录核对实际来源，升级格式前检查迁移预览，不要把旧位置的契约再复制成第二份动作定义。

## 保存、提交和放弃变更

编辑器提供 **保存** 和 **保存并提交**，两者用途不同：

| 操作 | 结果 | 适用场景 |
| --- | --- | --- |
| 保存 | 保存当前修改并执行后端校验，修改仍处于未提交状态，模型继续保持编辑锁。 | 分阶段配置、预览页面或暂时保留草稿。 |
| 保存并提交 | 先保存并校验，再填写修改说明，把当前修改写入变更记录。 | 一组配置已经完成并可以交给其他人继续使用。 |
| 取消 | 关闭编辑页；存在未保存修改时会提示确认。 | 不保留本次尚未保存的页面输入。 |
| 放弃变更并解锁 | 回到上一次提交的版本并释放编辑锁，操作不可撤销。 | 整组未提交修改都不再需要。 |

点击 **保存并提交** 后，为本次修改填写能够说明内容的提交信息，例如“补充编辑表单字段和查询权限”。

如果保存后提示后端校验错误，修改已经保存，但模型仍有需要处理的问题。根据页面警告或列表中的错误详情修正配置，再重新保存并提交。

## 维护已有模型

### 重命名、移动和删除

在模型未被编辑锁定时，打开行末的更多操作，可以重命名、移动或删除模型。

![重命名、移动和删除](.assets/business-model/model-actions.png)

- **重命名** 会改变模型标识。执行前检查页面、接口、逻辑和其他模型中的引用。
- **移动模型** 只调整模型在模块树中的位置。
- **删除模型** 前先确认它没有被其他模型、页面、流程或接口引用，并确认不再需要对应数据。

### 查看模型详情和投射模型

点击模型名称或 **查看详情**，可以查看基本信息、完整模型定义和投射模型。编辑器中没有未保存内容时，也可以点击 **查看投射模型**。

![查看模型详情](.assets/business-model/model-detail.png)

投射模型用于核对业务模型对应的数据模型、页面模型、接口模型、菜单模型和权限模型等结果。这里适合检查结果，不用于替代业务模型编辑器中的源配置。

### 查看变更记录

选择 **查看变更记录**，可以查看每次提交的时间、提交信息和作者。

![业务模型变更记录](.assets/business-model/change-history.png)

提交信息应写明本次修改的对象和目的，避免使用“修改”“调整”等无法帮助后续排查的描述。

## 在调试实例中验证

完成配置后，按以下顺序检查模型是否可以使用：

1. 在基本信息中打开 **启用模型**。
2. 确认索引页、新建表单、编辑表单和详情页已经按需要打开。
3. 点击 **保存并提交**，并填写修改说明。
4. 使用页面预览分别检查四类视图。
5. 在应用顶部的调试工具栏中启动调试实例；实例已经运行时，点击 **热刷新应用**。
6. 打开调试应用，检查模型菜单和索引页。
7. 新建一条测试数据，再依次检查查询、查看、编辑和删除。
8. 使用目标角色登录，检查字段权限、数据范围和操作权限。

验证不应停留在“页面能打开”。至少需要确认一条数据能够完成新建、查询、查看和编辑；启用了删除、工作流、自定义功能或导入导出时，还要分别验证对应路径。

## 常见问题

### 为什么不能编辑业务模型？

模型可能被其他用户锁定。查看列表中的锁定状态和锁定人，等待对方提交或解锁。

### 为什么保存按钮不可用？

当前页面没有检测到修改。确认配置值已经发生变化后再保存。

### 为什么保存后仍有错误标识？

打开错误详情，根据错误范围修正字段、关系、视图或接口配置，再重新保存。

### 为什么预览页面按钮不可用？

当前模型存在尚未保存的修改。先保存模型，再打开预览页面。

### 为什么新建或编辑表单缺少字段？

检查对应视图的 **表单字段**，确认字段已经加入，并检查字段访问控制。

### 为什么索引页没有显示预期列？

检查索引页的 **显示列**，并确认目标角色拥有相应字段的查询权限。

### 为什么服务端导出找不到新增字段？

先保存业务模型，再回到服务端数据导出配置中点击 **刷新字段**。

### 为什么调试应用中没有模型菜单？

确认模型已启用、不是附属模型、视图已启用，并且修改已经保存并提交。完成后，在顶部调试工具栏中热刷新应用。

### 为什么页面可以打开，却不能新建或更新数据？

检查对应的标准接口是否启用、访问控制是否开启，以及目标角色是否获得相应权限。

### 为什么修改没有出现在调试应用中？

确认修改已经提交，并对运行中的调试实例执行热刷新。
