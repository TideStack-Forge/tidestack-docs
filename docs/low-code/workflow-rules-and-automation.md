# 流程、规则与自动化

本页用于选择表达式、脚本、逻辑流、审批流和通知。先按动作特征选择唯一的主执行方式，再按需附加通知。

## 选择规则

| 需求 | 使用能力 | 不适合的情况 |
| --- | --- | --- |
| 字段默认值、显示条件、短计算 | 表达式 | 多步处理、外部调用 |
| 局部计算、少量分支和循环 | 脚本 | 跨多人、跨时段流程 |
| 查询、校验、转换、写入等自动步骤 | 逻辑流 | 人工待办与审批决策 |
| 申请、审批、驳回、转办、会签 | 审批流 | 纯系统自动任务 |
| 待办、结果或异常触达 | 通知 | 推进业务状态 |

逻辑流处理机器执行的短流程；审批流处理人参与的长流程。通知只负责触达，不负责决定流程走向。

## 配置顺序

1. 写清楚动作输入、成功结果和失败结果。
2. 短规则使用表达式；超过一行仍能局部完成时使用脚本。
3. 多个自动步骤使用 [逻辑流](../guide/tutorial/logicflow/) 编排。
4. 需要人工处理时使用 [审批流](../guide/module/approval-workflow/)。
5. 在待办生成、审批结束或异常发生处调用 [消息通知](../guide/tutorial/notification/)。
6. 使用成功输入、业务拒绝和系统异常各执行一次验证。

## 常见组合

| 场景 | 组合 |
| --- | --- |
| 保存订单前校验并计算金额 | 逻辑流 + 表达式 |
| 报销申请、审批和结果提醒 | 审批流 + 通知 |
| 合同审批通过后写状态并通知申请人 | 审批流 + 逻辑流 + 通知 |
| 定时汇总数据并发送结果 | 计划任务 + 逻辑流 + 通知 |

## 验收

- 同一个业务动作只有一个主执行入口。
- 逻辑流失败会返回明确错误，不会静默跳过节点。
- 审批流能定位当前节点、候选人和处理记录。
- 通知失败不改变已经完成的业务结果；需要强一致时，应在业务设计中明确补偿策略。
