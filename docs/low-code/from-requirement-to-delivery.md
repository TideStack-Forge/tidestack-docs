# 从需求到交付

使用本页把业务需求拆成平台任务，并在发布前逐项验收。

## 1. 定义业务边界

开始建模前写清楚以下内容：

- 核心业务对象，例如客户、合同或请假单。
- 创建、查看、修改和处理数据的角色。
- 必须由系统自动完成的动作。
- 必须由人审批或确认的动作。
- 上线后仍会变化的参数。

产出：一份对象、角色和关键动作清单。对象边界不清时不要创建多个模型。

## 2. 创建模型和标准页面

1. 创建应用和核心业务模型。
2. 定义字段、必填规则和模型关系。
3. 启用自动列表、表单和详情页。
4. 保存并提交模型。

验收：业务数据可以新建、搜索、查看和编辑。操作示例见 [完成第一个业务功能](../getting-started/first-business-feature)。

## 3. 承接业务动作

| 动作特征 | 使用能力 |
| --- | --- |
| 单个字段取值或短条件 | 表达式 |
| 局部多步计算 | 脚本 |
| 系统自动执行多个步骤 | 逻辑流 |
| 人工申请、审批、驳回或转办 | 审批流 |

验收：每个关键动作都有唯一实现入口，失败时能看到明确错误；不要用审批流承接纯自动任务，也不要把长业务链塞进一个脚本。

## 4. 配置访问和通知

1. 准备公司、部门、岗位和员工数据。
2. 创建角色并分配用户。
3. 配置菜单、页面、接口和数据范围权限。
4. 为待办、结果和异常配置通知模板。

验收：无权限账号看不到入口，也不能直接调用受限接口；目标用户能够收到通知。

## 5. 发布和验收

1. 提交全部模型、页面、流程和配置变更。
2. 在 **版本管理** 发布明确的逻辑版本号。
3. 创建或更新运行实例。
4. 使用普通业务账号完整执行一次创建、处理、通知和查询。
5. 使用无权限账号验证访问边界。
6. 记录版本号、验收账号、测试数据和验收结果。

发布被阻止时先清理未提交变更；运行实例异常时查看实例详情和平台日志。不要通过重复发布掩盖模型或配置错误。
